# 王翼棄兵 — 中世紀 3D 西洋棋

![雕刻的象牙王國騎士、主教與戴冠國王，在黑白大理石棋盤上對陣太陽帝國的羽飾戰士，每顆棋子頭頂上都飄著階級紋章](docs/board.jpg)

<p align="center"><sub>象牙王國對陣太陽帝國 —— 階級紋章升起、集結光環亮起，在第一步落下之前。</sub></p>

一款在瀏覽器中運行的電影級 3D 西洋棋遊戲。對立的文明 —— 歐洲中世紀的**象牙王國**、中美洲的**太陽帝國**，以及拿破崙法國的**大軍團** —— 以雕刻、綁定骨架的角色在黑白大理石棋盤上對陣，這些角色會行軍、攻擊、嘶喊，最終化為灰燼。雙方皆可招募三支軍隊中的任一支。

以 **Vite + React 19 + TypeScript + three.js** 構建，[chess.js](https://github.com/jhlywa/chess.js) 負責規則，**Web Worker** 搜尋引擎負責電腦對手。無後端、無帳號、無建置時資產管線 —— 它就是一個靜態網站。

```bash
cd web && bun install && bun run dev
```

## 功能特色

- **完整西洋棋規則** —— 王車易位、吃過路兵、升變、將軍、將死、困斃、三次重複局面、五十步規則，以及子力不足，全部透過 chess.js 實現。
- **綁定骨架的 3D 角色，而非西洋棋棋子** —— 十八座雕塑模型（每支軍隊六座），各自擁有 `idle`（待機）、`walk`（行走）、`attack`（攻擊）和 `death`（死亡）骨骼動畫片段，外加武器、盾牌與浮動的階級紋章。
- **雙方陣營絕不混淆** —— 每顆棋子站在所屬陣營繪製於棋格內的色帶上，並沿其剪影攜帶陣營邊緣光：近方為天藍，遠方為餘燼橙。色帶的*形狀*與顏色皆不同（普通雙色帶對尖刺日暈環），因此對色盲玩家、在手機上、在最暗的地圖上，以及在雙方招募相同雕塑的鏡像對戰中，兩邊都能區分。
- **三種軍隊造型，每方獨立選擇** —— 象牙王國、太陽帝國或大軍團，各有六座雕塑、動畫片段、武器家族與語音。可隨時在**設定 → 軍隊**中更換任一方；選擇會跨瀏覽記住。
- **棋子行軍，而非滑行** —— 被移動的棋子會轉向面對目的地，以自己的雙腿按照階級節奏走完距離，到達後再重新站定。騎士保留跳躍，在空中奔跑並以雙腳著地。
- **在行軍時脈上合成腳步聲** —— 每一次腳步落地都由同一個時脈觸發，該時脈也重新定時行走迴圈，因此聲音、沙塵飛濺與腳同時落下：步兵為皮鞋磨擦聲，神職人員為皮靴聲，鐵塔守護者為鎧甲碰撞聲，國王為緩慢而沉穩的步伐。
- **電影級吃子** —— 鏡頭推進，攻擊者在命中幀揮擊，火花飛濺，螢幕震動，防守者**從腳底向上**透過參差的光邊**燃燒殆盡**，散落飄離的光點（王國為冷冽的靈魂之光，帝國為熾熱的餘燼）。
- **格子易主** —— 當勝利者的靴子踏上剛清空的那一刻，其顏色**向內收合**覆蓋該格（此棋盤上所有其他光環皆向外擴散，因此反向運動清晰可辨），軍隊的印記在下方封印，舊占領者的石屑被揚起，而棋子挺直全身。在這之上，一段銅管旋律奏出完全五度上揚 —— 遊戲中唯一意味著*征服*而非暴力的聲音。這一切都與**被吃掉的棋子掛鉤**，因此交換步兵永遠不會聽起來像擊殺皇后。
- **隨階級加重的打擊** —— 步兵刺擊後繼續前進；騎士在衝鋒時劈砍，在空中留下一道鋼弧；鐵塔守護者的戰錘發出波動滾過石面，大廳隨後持續震動；國王**在受刑者頭上降下一道光柱**，敲響鐘聲，以黃金處決。每個階級都有其獨特的鏡頭推進、凍幀、揮擊重量與餘震。
- **施法者遠距擊殺** —— 皇后與法師從不縮短距離。他們在自己的格子舉起法杖，在水晶處聚集火焰，然後沿直線擲出：火焰在飛行中照亮大廳，在身體上炸開，直到屍體燃燒殆盡後，他們才走完所有距離並佔領格子。法師投擲**一發**法彈；女巫師投擲**三連發**，並在格子上留下一圈燃燒的火焰（王國為冷冽的巫火，帝國為太陽之火）。
- **十八種死亡嘶吼** —— 每個階級、每支軍隊各一種錄製語音，依屍體在螢幕上的位置調整聲像，壓低音樂一拍，並加入音高抖動使每次死亡聽來不同。每支軍隊以自己的語言死去：象牙王國咆哮呻吟，太陽帝國尖嘶與大軍團 —— 被射擊而非打擊 —— 先被抽走氣息，才發出聲音。
- **將軍警報** —— 當國王一被將軍，大廳本身立即反應：一盞紅燈在受威脅的王冠上方亮起，紅光從螢幕遠方邊緣滲入，鏡頭捕捉到低沉的隆隆聲。刻意保持安靜：湧動在不到一秒內消退，洗刷從不觸及棋盤，之後紅燈以低頻率持續呼吸，只要國王仍在將軍中。警告必須被*注意到*，而非*忍受* —— 警報點出危險中的王冠，卻不染色棋子或在玩家視線下移動棋盤。
- **七個戰場**，重新照亮整個世界 —— 天空、霧氣、石材顏色、棋格對比、火焰、飛鳥、攻城器械與電影調色 —— 且各帶來自己的音樂。
- ** 2D 戰術視角** —— 一鍵將鏡頭直接升至頭頂，將每顆棋子壓扁為印記標記，使任何格子都無法被隱藏。選擇與移動仍然有效。
- **三種引擎強度**，在主线程外執行，因此渲染迴圈永不阻塞。
- **AI 對戰 AI / 吸引模式** —— 讓兩個引擎自行對決，可控制節奏、暫停、自動重賽，以及隱藏整個介面的乾淨擷取視角。三種鏡頭行為：固定角度、跟隨移動中的棋子並拉近戰鬥，或緩慢繞著棋盤漂移。跟隨機構**傾向**於動作而非追逐它撞向大廳牆面，因此追蹤時畫面不再顫抖。AI 對戰 AI 的渲染也比遊玩中的遊戲更銳利 —— 無景深、較柔和的粒子、暗角與泛光。每場 AI 對戰 AI 對決現在**以勝負卡結束**：誰贏了、怎麼贏的、兩個引擎強度、紀錄、下一場對決的倒計時（可暫停），以及一鍵再賽一場或返回大廳。
- **不佔用棋盤的介面** —— 純圖示控制項，每個都有主題提示工具（名稱、單行說明、按鍵提示），走棋紀錄摺疊為角落符印，以及可收合為單一圖示的窄型展示列。一鍵剝除整個疊層以便錄影。
- **自動偵測圖形預設**（低 → 極致），若測量到的幀率持續偏低則自動降級，另支援 WebGL 內容遺失復原。
- **計時鐘**、悔棋、認輸、翻面、可複製的 PGN、帶物質分數的俘虜托盤。
- **戰場統計**在左上角：每支軍隊損失的棋子數與在戰場上的時間，即使在無時限對決中也會即時跳動。

## 快速開始

需要 **Node 20+**。建議使用 [Bun](https://bun.sh)；npm/pnpm 亦可。

```bash
git clone <your-fork-url>
cd <repo>/web

bun install
bun run dev        # http://localhost:5173
bun run build      # 生產建置至 web/dist/
bun run preview    # 提供建置好的打包
```

`web/dist/` 中的建置輸出是純靜態網站 —— 放到 GitHub Pages、Netlify、Cloudflare Pages 或任何靜態主機上即可。無需環境變數即可運行遊戲。

| 設定 | 齒輪圖示 —— 軍隊、戰場、圖形預設、吃子電影效果、棋盤擺動、排隊落子、思考時間、聲音 |

沒有拖放：移動超過 8px（手指為 16px —— 玻璃上的點擊總會漂移）的按壓被解讀為鏡頭擺動，因此從棋子處環繞絕不會移動棋子。選擇與移動都在放開時判定。

**被棋子後方遮擋的目的地仍只需一點。** 這些是站在 1.02 公尺見方格子上的人偶，從低鏡頭看去，棋子要移動到的格子通常*在*某個人身後而非旁邊。在開局位置以真實構圖與碰撞體測量，騎士的兩個目標格在桌面視窗上有 **88% 被遮擋**（手機上 61–67%），而 `f3` 內只有 11% 的像素判定為 `f3` —— 其餘都擊中前方的 `f2` 兵，因此點擊選了兵而騎士從未移動。棋盤現在以一條規則解決這些點擊：**棋子為它所站的地面發言，僅此而已。** 指向發光的格子就得到那個格子，無論前方站了什麼；指向棋子自己的格子就得到該棋子，因此選擇棋子、取消選擇、點擊敵人攻擊都維持不變。每個被遮擋的目的地也會在遮擋其身前的身體*上*繪製其瞄準環，因此格子既能被看見也能被點擊。詳情與數據：[點擊棋子後方的格子](web/README.md#clicking-a-square-behind-a-figure)。

鍵盤快速鍵（在欄位中輸入時忽略，且**不會在手機上顯示** —— 見[只在有鍵盤處顯示按鍵提示](web/README.md#key-hints-only-where-there-are-keys)）：

| 按鍵 | 動作 |
| --- | --- |
| `F` | 將鏡頭翻到另一邊 |
| `T` | 切換 2D 戰術視角 |
| `H` | 開啟 / 摺疊紀事（走棋紀錄與戰利品） |
| `C` | 切換電影模式（隱藏整個介面） |
| `Space` | 在展示模式中暫停 / 繼續播放 |
| `Esc` | 關閉設定面板、鏡頭選單、紀事或開啟的提示工具 —— 然後收回一步排隊落子 |

**手機從未被要求按任何鍵。** 上述每個提示 —— 提示工具中的按鍵提示、`(T)`/`(F)`/`(C)` 提醒、升變橫幅的 *OR PRESS Q R B N*、*SCROLL TO ZOOM*、*CLICK TO SKIP* —— 過去在觸控裝置上也印了出來：**在螢幕空間最稀缺處有 13 個地方命名了該裝置沒有的按鍵或鼠手勢**。它們現在會先檢查，而裝上鍵盤保護殼的平板在第一次收到真正的按鍵時會取回其按鍵提示。手勢不同的地方用詞也跟隨手：*PINCH TO ZOOM*、*TAP TO SKIP*、*TAP A FIGURE*。

### 在電腦思考時排隊落子

棋盤過去在你落子的瞬間變得**失聰**。電腦回應期間的所有點擊都被丟棄 —— 包括已經完全知道下一步要怎麼下的玩家的點擊。

那段沉默持續多久是量出來的，不是猜的：透過真正的搜尋在無頭模式下重播完整對局。引擎在簡單上花 **7 毫秒，中等 615 毫秒，困難 3.07 秒**（平均；困難峰值 3.58 秒），而簡單被下限設為 420 毫秒以免即時回應顯得像機器人。然後回應被*執行* —— 行軍是 0.34–2.4 秒的行走，吃子再加上整個戰鬥節拍 —— 棋盤在整個期間保持鎖定。在困難上，每步是**四到六秒**，而你的計時鐘還在跑。

因此你現在可以在等待期間瞄準下一步。點擊你的棋子，點擊它的格子；該步被*保留*而非執行，在回合回到你手中時立即出發 —— 幾乎不花時鐘上的時間。

**而且你可以堆疊最多五步。** 一步排隊落子填補一次等待；在快棋中你已經知道接下來三步。每一步都是瞄準前一步留下的棋盤 —— 排隊騎士到 `f3`，下一步從 **`f3`** 開始，即使木頭還站在 `g1`。預設是三步，這是測量出來的數字而非口味：在 241 條對騎士的五步深鏈中，第一步在電腦回應後存活 59.6%，之後每一步存活率*更高*（69.9%、72.2%、90.9%、72.0%）—— 一旦第一步活下來，對局就照你計劃的方向走。整條鏈都會丟棄：41.7% 跑到兩步深，30.1% 三步，19.7% 全部五步。所有排隊的落子中，35.5% 實際被執行，或**每條鏈 1.53 步**。超過三步後，你排隊遠多於你實際走的，因此提供五步但非預設。

**而且你可以設定電腦等多久。** 設定裡有*電腦思考時間*：即時、0.4 秒、1.5 秒、3 秒或 6 秒。它是回應的下限，從不是搜尋的上限 —— 一個確實需要領主三秒的位置仍然花三秒，且沒有設定會讓引擎變弱。侍從在 7 毫秒內回應，因此在該等級下限就是整個等待：設為 6 秒，排隊落子的每個環節都舒適好試，從瞄準到看著它被回應殺掉。選擇會跨瀏覽記住。

- **提供的格子是幾何的，不是合法的。** 城堡被提供整條線即使有兵擋路，兵被提供兩個對角線無論是否有東西可吃，王被提供兩個易位格。落子瞄準的是一個尚不存在的位置，而擋路的棋子可能正是要移動的那顆。
- **三種收回方式，表達三種不同的意思。** 懸浮在最後格上的小 **X** 移除**那一步**；點擊排隊落子自己的起始格移除**它及其之後的一切**；`Esc` 或點擊棋盤外丟棄**整條鏈**。
- **如果第一步死了，鏈跟著死。** 它後面的所有步驟都是為一個永遠不會發生的棋盤規劃的，因此被丟棄而非盲目執行。
- **王冠提前選好。** 排隊的兵推進到最後一線會*當場*打開慣常的選擇器，因此執行時不會有任何中斷。
- **如果回應殺死了它，它被丟棄** —— 從不盲目執行。兩個格子閃紅一次後清除；沒有對話方塊，因為你剛看著殺死它的那步。
- **將軍立即終結計劃。** 當電腦的步讓你的王受到攻擊的瞬間，整個隊列消失 —— 與那步一起，而非數秒後 —— 而當你被將軍時，只能瞄準實際能回應的格子。
- **四次中有三次存活。** 放置時合法的排隊落子中，**73.9%** 在電腦回應後仍然合法；其餘死於將軍（18.0%）或路徑被封（8.1%）。隨機排隊則降至 ~33–40%。

在棋盤上，排隊落子明確是*意圖*：冷錫白色，在每步落子使用的綠/紅/紫/天藍色調之外，且在實心標記處斷裂。

**鏈畫成一條箭頭，而非一堆。** 計劃通過的每個格子保留一個暗淡的空心虛線環，只有它*結束*的格子才獲得明亮的近白邊框 —— 四個硬角支架框住棋格，中間一個實心小點。這是棋盤上唯一不轉的標記，因此它始終對齊它聲稱的地面。細線在鏈節間呼吸，使整個計劃一眼可讀。棋子從不移動，直到落子執行。

**而且每條線現在都有方向。** 過去線在兩個格子間完全均勻，因此鏈節看起來完全一樣反著讀 —— 在 23923 條三步鏈中，五分之一有自己的兩條線在石上交叉，另有 5% 的鏈節兩端都與另一鏈節共用。在那些時刻，標記無法回答「哪個方向？」，因此現在線自己回答：每條線是一顆彗星，在離開的格子處是近乎黑色的細髮，在進入目標格子時膨脹成明亮的寬燃燒。它在同一方向變得*更粗*且*更亮*，因此即使在交叉處、在手機上、在黑暗大廳中、用色盲眼睛仍然可讀。而且整條鏈越往後越冷：下一步要執行的是亮鋼色，等待在其後的漸暗向冷錫白色 —— 因此你既能看見每步的方向，也能看見計劃的順序，無需讀任何數字。

**而且鏈中每個格子都戴著它的數字。** 一條箭頭說計劃*結束*在哪；它不說第二步會怎樣。三步排隊落子留下三個由線連接的相同環，從低鏡頭看去這些線彼此交叉，你能讀回來的只有一組格子。因此每個格子帶著它的回合 —— 1、2、3 —— 以棋盤邊緣階級與線條字母相同的雕刻襯線切割，懸在石面上方並在任何遮擋棋子之前繪製。它是帶柔和暗光環的裸數字，從不是圓盤：撤銷幣是你這裡唯一按的東西，其他任何東西都不准看起來像它。下一步要執行的最亮，尾巴在其後漸暗。單一步排隊落子不帶數字 —— 孤獨的「1」回答了一個沒人問的問題。

**而且排隊落子現在有自己的聲音。** 為計劃拿起棋子和實際排隊落子是幾乎同音量的相同乾木板敲擊，因此在引擎回應中已經在行軍和碰撞時，耳朵無法分辨*聽到了你*和*它在隊列中* —— 而且沒有任何東西說哪個鏈節剛落下。因此落子後在敲擊下留一個小鈴：非常安靜，漸強而非敲擊，半秒內消失。它隨鏈爬上五音階梯，因此堆疊三步會播放一個小小上揚的樂句而非三個相同的輕拍，你能聽見你的計劃有多深而不必轉開視線。音符來自計劃*著陸*的格子，而非木頭所站的格子。

**將軍不等輪到它。** 計劃是為沒有人在向你的王吼叫的棋盤畫的，因此將軍回應不是排隊落子失敗的另一種方式 —— 它是計劃的終結。過去它被視為另一種失敗：鏈在整個將軍步中保持亮著，只在棋盤回到你手中時才死。在中間引擎的 949 次等待中測量，其中 190 次以將軍結束，之後排隊落子仍可執行**7.9%** —— 對比安靜回應後的 79.2% —— 整條鏈存活 3.2%。而十五個倖存者中有十四個是王恰好走到合法位置，這是意外而非計劃。因此隊列現在與殺死它的那步**一起死**：標記在將軍落下時清除，帶著聲音與輕微震動，沒有第二次紅光閃 —— 王自己的格子已經在回應了。

提供的格子也會變。因為視窗在將軍步執行期間開著，你可能會瞄準永遠不會被允許使用的格子：在那些將軍位置中，一般慷慨的幾何亮起的 10470 個格子裡，只有 **5.2%** 實際可執行。當你的王受到攻擊時，你瞄準的第一步被削減到回應將軍的步 —— 鏈的其餘部分，瞄準著沒人能看到的棋盤，保留完整幾何。

**而且有一個按鈕可以收回一步。** 一個帶交叉線的深色小幣在鏈的最後格上方輕輕上下浮動，使其讀來像控制而非石面上的另一個標記。點擊它，最後一步排隊落子消失，小幣跳回鏈的新末端 —— 它是悔棋，不是垃圾桶。它在鏡頭擺動時始終面向你，繪製在所有東西之前 —— 包括擋路的棋子 —— 並在游標下暖成餘燼，因為它是摧毀某物的按鈕。撤銷過去總能用 `Stray` 點擊達成；這些都不可見，而在手機上有一半甚至觸達不到。

設定裡有*可堆疊步數* —— 一、三或五 —— 就在開關正下方，並跨瀏覽記住。

設定中可關閉，預設開啟。規則與完整測量數據：[在電腦思考時排隊落子](web/README.md#queuing-a-move-while-the-machine-thinks)。

## 介面

棋盤佔據螢幕；每個面板若非短、在角落，就是可摺疊的。

| 區域 | 內容 |
| --- | --- |
| 左上 | 誰的回合、思考脈衝、將軍橫幅、展示對決計數器 —— 及其下方的戰場統計 |
| 右上 | 計時鐘，然後是圖示列 —— 收回、認輸、新對決、聲音、全螢幕、翻面、戰術、鏡頭選單、設定 |
| 右側： | 列：戰利品（兩個俘虜托盤與物質分數）在橫條下方，然後是**走棋紀錄**沿列其餘部分在棋板旁執行。僅桌面與平板 —— 手機上兩者都摺疊進紀事 |
| 左下 | 紀事符印 —— 帶走棋計數器的角落按鈕，顯示或隱藏紀錄（`H`） |
| 右下 | 展示列，僅在展示對決期間 |

- **戰場統計**（`.mc-tally`）直接位於回合石板下方：每支軍隊一行，帶其紋章、**損失**的棋子數與其在戰場上的**時間**，加上標題中的戰鬥總長度。移動中的軍隊是亮行 —— 完全不透明度，及其天藍/餘燼色的洗刷與細線 —— 因此面板無需第二個標籤就能說誰的時鐘在跑。新鮮的埋葬會膨脹並閃爍其損失計數一次（`mc-tally-toll`）。它只讀不碰：面板是 `pointer-events-none`，因此該角落的每個點擊仍然到達棋盤。
- **經過時間不是時鐘。** `ClockState` *倒數*且僅在選擇了時鐘時存在；`ElapsedState` 始終累加，因此無時限對決仍報告每方花了多久。`GameController` 將牆時間計入移動中的那一方，並在每個改變誰在思考的事件重新指向時鐘 —— 已執行的步、暫停、悔棋、戰鬥結束 —— 因此暫停的展示不向任何人收費。統計通過 `controller.getElapsed()` 在自己的 500 毫秒脈衝上**即時**讀取，而非從快照讀取：核心僅在真實事件時發布，而經過的一秒不應重新渲染整個介面。

- **提示工具**（`src/ui/Tooltip.tsx`）取代瀏覽器的原生 `title`，後者出現太晚無法解釋圖示。每個氣泡帶有控制項名稱、一句解釋，以及有快速鍵*且*裝置有鍵盤時的按鍵提示。它在 110 毫秒後打開，然後在沿列掃描的其餘部分**立即**打開，選擇保持在螢幕邊緣內的螢幕側，在觸控按壓時閃爍 1.8 秒（觸控沒有游標停留），並在 Escape、失焦或滾動時關閉。氣泡渲染在其錨點內而非通過主體入口，因此能在全螢幕下存活。
- **按鈕不是橫幅。** 大廳的兩個常設動作過去橫跨整個選單面板寬度 —— 400px 金色，王冠與「TAKE THE FIELD」佔 39%，齒輪與「SETTINGS」僅 23%，以字體的真實字母寬度測量而非目測。現在兩者都在自己的標籤後截斷，並**並排**在一行上，各佔一半寬度。堆疊時，它們讀來像兩個相等選項的清單；配對時，它們讀來像一個決定 —— 走，或先設定 —— 而該行給上方集結面板拿回一個按鈕的高度。它們的字型、內邊距與間距隨螢幕縮放，因此文字讀來像按鈕的要點而非擱淺在中間的東西。它們仍在最小螢幕上滿足 44px 觸控目標，而主要按鈕以字重和字母而非寬度區分 —— 兩個不等的半會讀來像兩個無關的控制項。低於 400px 寬度時配對退回堆疊，因為換行的「TAKE THE / FIELD」比欄還糟。
- **展示列**是單一 26px 圖示行 —— 播放/暫停、0.5×–4× 節奏、三種鏡頭行為、循環、重啟 —— 保持 74% 不透明度直到游標停留，並可摺疊為單一場記板圖示。暫停以呼吸的播放按鈕顯示，而非大標籤。
- **電影模式**（`C`）完全移除疊層，留下一個小還原按鈕，因此螢幕擷取只有棋盤。
- **勝負卡**（`GameOverModal.tsx`）結束每場戰鬥，包括展示。過去每當展示循環啟動時它都被**抑制** —— 最多人觀看的模式是唯一不說誰贏了的，只是靜默重置。現在它也為展示升起，以自身的框架：對決編號、獲勝紋章與遊戲如何結束、兩個引擎強度與步數、紀錄，然後**另一場對決** / **大廳**。有兩樣東西為觀眾而非玩家調校：背景保持**薄且無模糊**（35%，無模糊）因為在展示中最終位置*就是*畫面，而卡片**等待 2.2 秒**讓結束電影能完成推向倒下國王的推軌而非被面板切斷。
- **循環，視覺化。** 自動重賽啟動時，卡片帶著即時的**NEXT DUEL IN _n_s** 桿和一個**HOLD** 按鈕，當場解除循環 —— 因此棋盤不能在觀眾說話中途重置，且停止它不必去找列。下一場對決前的暫停從 6.5 秒延長至**9 秒**以留下讀結果的時間。倒計時在自己的**100 毫秒脈衝**上從控制器讀取截止時間（經過的一秒不應推快照通過整個疊層），而**另一場對決**通過 `restartDemo()` 路由，使兩個引擎強度、節奏與對決計數器存活 —— 將它通過 `startMatch` 發送會悄悄地將對決降級為對電腦的遊戲。
- **這裡沒有任何東西由引擎觸發。** 神槍手的步槍射擊過去在整個介面上關閉一個全螢幕瞄準畫面；它與其額外的鏡頭推進一起被移除，因此步槍擊殺在大廳中觀看就像其他所有擊殺一樣（見[火藥戰鬥](#火藥戰鬥手槍步槍滑膛槍與野戰炮)）。

### 閱讀升變選擇器

兵到達最後一線打開遊戲中唯一真正的模態時刻，而它過去是螢幕上最難讀的東西：四個無標籤的雕塑模型懸在棋盤中央，在棋盤深度。以出貨的構圖測量，每個候選者在 **1440×900 桌面上高 103px，390×844 手機上高 38px**，每個候選者的剪影有 **32–37%（桌面）和 94–100%（手機）** 被身後遠方軍隊重疊。沒有任何東西說哪個是哪個，而在這支軍隊中無法猜測：每個軍官都是皇家高度，因此城堡、主教和皇后只在他們拿的東西上不同。

選擇器現在以模態呈現：

- **命名。** 每個候選者站在一塊**石銘牌**上方，帶有階級自己的紋章剪影 —— 與其在棋盤上戴的同一個 —— 拼出階級與選擇它的鍵。銘牌是精靈圖，因此它從任何鏡頭面向玩家，包括平坦戰術視角，且它本身就是點擊目標（最容易擊中的）。
- **錨定在鏡頭，非棋盤。** 該行放在鏡頭前一個求解的距離，因此它在每個構圖下讀來相同，且永遠不會隱藏在棋子列中。
- **為可視區域求解。** 寬螢幕上四個並排；螢幕太窄無法容納四個可讀人物並排（直向手機）時為 **2×2 格**。距離求解使整個選擇器填滿可視區域綁定軸的 84% —— 手機上高 38px 的人物現在約 ~115px，桌面約 ~197px。
- **背後有遮罩。** 一塊暗板掛在候選者身後，每幀調整為可視區域，現有的電影景深聚焦在選擇器而非棋盤上。身後的軍隊讀來像變暗、模糊的背景，而非與候選者競爭的雜物。
- **可用鍵盤回答。** `Q` `R` `B` `N`（或 `1`–`4`）做選擇，印在銘牌本身上；選擇器打開時那些鍵屬於它，不屬於其他任何東西。
- **游標停留反饋。** 游標下的候選者升起、放大、照亮其基座與銘牌，游標變為游標 —— 進入時鳴叫一次，非每幀。
- **沒有東西畫在它上面。** 浮動的階級紋章與 X 光格子瞄準環刻意繪製在遮擋其身前的任何東西*之中* —— 這就是它們的全部意義 —— 而這個許可也把它們直接帶過選擇器：身後軍隊的紋章落在候選者及其銘牌上方。坐在較高的層不能單獨修復這個問題，因此當選擇器打開時這兩個疊層退下，並在關閉瞬間回來。你自己的紋章設定不受影響；這是獨立的暫時靜音。

## 遊戲模式

| 模式 | 說明 |
| --- | --- |
| **玩家對電腦** | 選擇你的顏色、引擎強度與可選的時鐘 |
| **雙人** | 同一螢幕輪流；視角**保持不動** —— 用手 `F` 翻面，或在回合間開啟自動擺動（見下方） |
| **AI 對戰 AI** | 兩個引擎自行對決 —— 每方強度、0.5×–4× 節奏、自動重賽、靜止 / 跟隨 / 環繞鏡頭、可摺疊列、結束時的勝負卡 |
| **吸引** | 離開選單 30 秒，AI 對決在它背後開始 |

時鐘：無、5、10 或 15 分鐘，繪製成沙漏。

**輪流不會替你轉棋盤。** 它過去會：每步後轉半圈，預設開啟。這是遊戲中最重的鏡頭移動，以西洋棋節奏大約每 15–30 秒觸發一次 —— 不請自來，就在玩家已經在追蹤的步結束時，這正是鏡頭讓人反胃的方式。坐在一個螢幕前的兩個玩家不需要棋盤重新定向；他們需要保持方向。因此擺動**預設關閉**，你的選擇跨瀏覽記住。在*設定 → 回合間擺動鏡頭*中重新開啟，現在花 **1.8 秒而非 1.15 秒**，因此它讀來像大廳在轉而非切換。手動翻面不變 —— `F` 或翻面按鈕在你要求的瞬間旋轉視角，而要求它正是讓它舒適的原因。

大軍團通體海軍藍與金色 —— 紅色鑲邊、黃銅帝國鷹、白色馬褲、雙角帽、沙平與熊皮帽 —— 每個階級一個剪影：拿破崙的側戴雙角帽與佩劍，指揮官的月桂花冠在馬雷諾劍上方，元帥的羽飾帽與大衣襬在棋盤上最長的槍管上方，重騎兵的馬鬃頭盔在鋼胸甲上方，砲兵衛士的熊皮帽在他拖行的野戰炮後方，以及步兵的滑膛槍。**這是唯一用火藥戰鬥的軍隊**（見[火藥戰鬥](#火藥戰鬥手槍步槍滑膛槍與野戰炮)）：拿破崙用手中燧發槍了結事情，她的指揮官在左手仍持馬雷諾劍的同時做同樣的事，元帥跪在單膝上等完整場遊戲並用步槍射擊，線列步兵齊射，以及砲兵架好並操作它拖行的炮。只有重騎兵仍然縮短距離，軍刀優先 —— **這支軍隊中沒有任何人施法**。

更換軍隊會重新下載其名冊，因此交換等待螢幕上任何戰鬥結束，拿下舊棋子並豎立新棋子（冷取快取時一兩秒）。給**雙方**同一支軍隊則只下載一次：遠方渲染完全相同的雕塑，重新染成深色馬具使兩支部隊永遠不會變得無法區分，並與它借用的那一側共用一組動畫片段。

馬具染色不是讓一方清晰可讀的東西 —— 它不能是。兩個*不同*的軍隊都保留自己的繪製紋理，因此在一般情況下染色從不運行。棋子屬於哪一方因此以三種不同管道說了三次：**繪製在其所站棋格上的色帶**、**沿其剪影的邊緣光**，以及**階級紋章** —— 近方為天藍，遠方為餘燼橙。色帶在形狀上也不同（王國的普通雙色帶對帝國的尖刺日暈環），因此答案對色盲玩家以及黑暗大廳都存活。色帶是*繪製*而非加到棋格上的：舊的加性發光消失在每個發光的石格中，這是棋盤的大多數。邊緣是在溶解著色器旁注入的菲涅耳邊緣，在色調映射之前加入，因此它與影格一起調色而非坐在它上面 —— 而且它在武器上，因為平舉的滑膛槍是剪影的一部分。

因為答案給了三次，**每種表達都可以安靜** —— 且必須是。一起調高這些標記會淹沒它們正在標記的棋子：邊緣光從論廓散開越過制服，每個棋子下方的光向上反彈顏色到其腿上，因此手繪雕塑的大廳讀來像藍色與橙色形狀。邊緣光現在保持在論廓的掠射薄層，地板光保持在靴子下方的呼吸，而頭頂的紋章 —— 唯一不覆蓋模型任何部分的標記 —— 保持明亮。顏色告訴你哪一方；雕塑仍然是你在看的東西。

這種共用是軍隊載入為**序列化**的原因，以及為什麼要求已經站著的軍隊完全不做任何事。應用程式在你的瀏覽間記住軍隊，並在第一次下載開始之前將它們交給棋盤，因此任何非預設選擇過去都同時開始交換與第一次載入。兩個執行填入了相同的名冊表，而當雙方都是同一支軍隊時，借用方拿著第一個執行的雕塑，而它借用的一方已被第二個執行的取代。它們停止了共用動畫片段，而借用名冊保留了自己的片段地址 —— 那一側永遠無法取得另一個行軍、打擊或死亡。它在棋盤上滑行並在不揮舞的情況下擊殺，而另一側完美地動畫。給雙方選擇同一支軍隊是每次都觸發它的唯一方式。

### 地圖是地方，不是濾鏡

新版地圖的第一個版本只是重新照明，僅此而已，而那是個錯誤。天空顏色、霧氣、火炬強度與電影調色可以令人信服地將*同一個*廢墟場地從清晨移到午夜 —— 但它們不能讓它變成沙漠或雪地。將石頭漂白成赭色並在頭頂放個白熱的太陽產生了一個非常明亮的圍城。區分那些地方的不是落在地面的光，而是**站在上面的東西**。

因此每個主題現在也指定自己的裝飾，從一個小詞彙表：樹叢（針葉林、棕櫚或光禿死木）、岩石散佈（沙丘、漂礫或雪堆）、幾塊立石、積水與天氣場。所有東西在啟動時建造一次，然後按主題顯示、隱藏與重繪 —— 雨林已經遵循的相同規則 —— 因此切換地圖從不在影格中分配幾何，而完整裝飾的地圖只花幾個實例化繪製呼叫。

場景就是場景：**都不准上棋盤。** 所有東西都安排在清晰半徑外，遠遠超過最後一線，因為站在格子之間的道具不是妨礙讀取位置的氣氛。第一次建構意外打破了那條規則 —— 一個鍍金方尖碑頂在理應放置它的通行*之後*建立，因此五個全尺寸站在中間四個格子上，整個天氣場在開幕影格堆疊在那裡。兩者都修復了，每個散佈的水池現在開始時是**空的**而非堆在中心，因此任何東西永遠不會畫在沒人選擇的地方。無頭重建裝飾並傾倒每個變換：任何地圖上最近的場景現在離中心 23.6 公尺，而棋盤只延伸到 4.1 公尺。

**雨、雪與沙塵暴是同一個系統。** 它們不是三個粒子引擎；它們是同一條條紋場，唯一不同的是偏離垂直的角度、墜落速度與每條條紋的繪製長度。雨偏 15°，以 19 公尺/秒墜落成長細線；雪接近垂直，以 1.7 公尺/秒墜落成短胖翻滾片；沙偏 75° —— 幾乎不墜落，只是*被攜帶* —— 以 24 公尺/秒，貼著沙丘而非填滿天空。每條條紋也沿自己的軸移動而非直線下墜，因此斜向的雨滴像它畫的那樣移動而非側向滑過自己。

那些條紋是平面四邊形，因此側看會消失。與其每幀旋轉 700 個實例面向鏡頭，該場是以棋盤為中心的**圓柱**，整個組旋轉面向鏡頭：繞自己的軸旋轉均勻散射的點的分佈留下相同的分佈，因此這是精確的而非近似，且每幀只花一次旋轉而非七百次。

### 地方需要地標

裝飾給地圖地面覆蓋，而地面覆蓋仍然只是*地形*。散佈的樹、岩石與雪堆令人信服是鄉間的地方，但它不是你能說出名字的地方：霜落與風暴守望都是「壞天氣中的樹與岩石」，直到其中之一有艘凍結在雪堆中的長船。地形告訴你在天氣做什麼。地標告訴你在哪裡。

因此每個地圖現在也在平原上豎立一座雕刻紀念碑，複製兩到三次到棋盤周圍的環上：

- **太陽神廟** —— 一座巨大的蘚蝕羽蛇頭，下顎刻有字形。
- **黎明宮廷** —— 一座毀壞的圓形瞭望塔，半個城垛已倒塌。
- **沙丘堡壘** —— 一座風蝕的戴冠國王巨像，埋在沙中到肩膀。
- **霜落** —— 一艘在雪中傾斜的擱淺長船，龍首仍豎著，索具結冰。
- **風暴守望** —— 一座屋頂被掀掉的烽火台，火盆在雨中敞開。
- **黃昏圍城** —— 圍城穿過的那座城門吊閘：吊橋歪斜垂著，石頭燒黑。

**它們站多遠是求解的，不是選的。** 每個地圖運行自己的霧密度，而且不低 —— 黎明宮廷在 0.0085，黃昏圍城在 0.019，厚兩倍以上。一個固定的環會在一個地圖上把相同的雕塑放在清晰空氣中，在另一個地圖上放在霧牆後。指數霧保留物體顏色的 `exp(-(distance × density)²)`，因此固定分數存活的距離是 `sqrt(-ln T) / density`，按地圖求解。保持 **T = 0.45** —— 剛好不到一半的顏色存活，因此地標明確是東西且明確是天氣的一部分 —— 將環放在黎明宮廷 105 公尺、雨林 85 公尺、沙丘 78 公尺、雪地 74 公尺、風暴 54 公尺、黃昏 47 公尺。所有六個在影格中重量相同。

它們是剪影道具，並如此建造：每地圖一座雕塑，**僅在該地編排時下載**（啟動時六個 GLB 顯示一個會在軍隊已經拉動的十二個骨架上浪費五個下載），從不投射陰影 —— 陰影鏡頭只覆蓋棋盤 —— 並在低圖形預設上與其他戰場道具一起完全關閉。每個副本在到達時測量而非信任：按自己的高度縮放，居中，並站在自己的最低點上，因此它坐在地面上而非懸浮或沉入其中。

其餘仍然成立：**沙丘堡壘**是唯一幾乎從頭頂正上方照明的地圖，這使兩支軍隊先變成剪影再變成顏色 —— 與黃昏相反的問題，也是其棋格是棋盤上最深棕色的原因。**風暴守望**是火炬*正在輸*的地圖，而**黃昏圍城**現在是最暗的地面。

### 選擇器

戰場選擇器過去是一排 CSS 漸層。漸層是地圖*調色板*的誠實總結，但對地點完全隻字未提 —— 兩個藍和一個灰無法告訴雪地與暴風雨有何不同 —— 因此它給玩家沒有理由嘗試他們還沒選過的地面。每個地圖現在帶著自己的繪製定場鏡頭，七個作為一個系列完成，因此該行讀來像一組而非七張庫存圖片。

藝術是裝飾層疊在舊調色板漸層**之上**，而非替代它：漸層保留為卡片的背景，因此仍在下載的卡片（或永遠不到達的）留下仍然讀來正確的选择器而非一排空孔。卡片被調暗並稍微去飽和，使金色標籤保持最亮的東西；只有選中的地圖完全亮起。

**軍隊**卡片現在以相同方式繪製，在同一個系列。它們以更尖銳的形式有舊問題：馬具漸層總結軍隊的*顏色*，而顏色不是軍隊 —— 海軍藍、白與紅是旗幟，不是站在火藥煙中的一排沙平，而三條斜紋告訴玩家太陽帝國實際部署的東西。每個造型現在帶著自己的繪製Banner —— 騎士在淡黎明下穿板甲，黑曜石與鳳頭鵑羽在階梯金字塔前，一排滑膛槍在硝煙後 —— 鋪在相同的馬具漸層上，與地圖相同的調暗、游標停留升起與選中全亮行為。色板從 1.5rem 長到 2.5rem 高，因為 24px 信中的繪畫是一抹。

```
        ├── assets/         軍隊造型：每文明的模型 / 片段 / 語音 URL
        └── components/ui/  shadcn/ui 基本體
```

## 架構

渲染與規則完全解耦：**西洋棋核心發射事件，場景訂閱它們。** `src/core` 中沒有任何東西匯入 three.js，因此遊戲邏輯可在無頭模式下測試，且渲染器可替換。

### 移動流程

1. 玩家（或 worker）產生一步 → `GameController.tryMove`。
2. chess.js 驗證它，控制器建構一個 `MoveEvent` —— 吃子、易位車行程、吃過路兵格、升變與將軍旗標。
3. 控制器**等待場景註冊的動畫器**，因此引擎永遠不會在棋子仍在滑行時移動。
4. React 從每次變化後發布的不可變 `GameSnapshot` 重新渲染。

### 狀態

只有一個真相來源（`GameController`）。React 通過 `useGameSnapshot` hook 讀取它，該 hook 訂閱發射器並返回最新快照 —— 無全域儲存，無將遊戲狀態 prop drilling 到場景中。

預設從 GPU 字串、核心數與裝置記憶體首次載入時自動偵測。引擎在測量到的幀率持續低於 40 FPS 時自動降一級。像素比例上限為 2（低為 1），遺失的 WebGL 內容顯示重新載入提示而非黑畫面。

### 黑畫面復原

某些驅動程式 —— 尤其是 Mesa 的軟體光柵化器，這是沒有硬體加速的 Linux 機器退回去的地方 —— 在完全正常的介面下繪製全黑場景。已見過三個獨立原因：後處理合成器返回空緩衝區、PMREM 反射探針取樣為 `NaN`（在精靈圖繼續繪製時毒害每個發光的表面），以及陰影圖。

引擎在未被要求的情況下處理所有三個：

- **探針自測**（`scene/diagnostics.ts`）—— 啟動時，一個*僅*由新建造的探針照亮的白色球體被渲染到 8×8 緩衝區並讀回。黑色表示探針不可用，因此它被丟棄，同色的環境天空光接管。
- **影格看門狗** —— 影格在前八秒內在五個點（中心加四個象限）取樣五次。全部五個都必須在丟任何東西之前讀回黑色，然後每次失敗的樣本剝掉一層：後處理 → 反射探針 → 安全渲染。
- **通知解釋發生了什麼**，一旦它一路退回安全渲染，選擇會記在 `localStorage` 中，因此下次瀏覽以畫面開始。

**設定 → 畫面**中的手動控制：

| 控制 | 效果 |
| --- | --- |
| 亮度 | 色調映射曝光倍率，60–180% |
| 安全渲染 | 無合成器、無反射探針、無陰影圖，+20% 曝光 |

URL 中的 `?safe=1` 從第一幀強制安全渲染，驅動程式字串被列印到控制台（`[scene] gpu: …`）並顯示在圖形預設下方。

## 角色動畫

每顆棋子是一個綁定骨架（蒙皮）的角色，最多六個骨骼動畫片段，在其軍隊的 `animated` 名冊中按階級宣告（`ARMY_SKINS` 在 `src/assets/generated.ts`）：

| 片段 | 播放時機 |
| --- | --- |
| `idle` | 循環戰鬥姿態，每棋子去同步化使軍隊不同時呼吸。大軍團的元帥**站著待命**，步槍放下：他過去持蹲姿等整場遊戲，讀來像永久卡在掩體中，因此蹲下移到唯一有價值的地方 —— 他的 `aim` |
| `walk` | 循環原地行軍，重新定時於正在進行的移動節奏。片段自己的行軍長度是**測量**而非假設（`gaitCycle()`），因為生成器交回從一個迴圈（`spear-walk`，1.13 秒）到三個（`casual-walk`，4.23 秒）的任何東西。它仍然必須是*行走*：0.5 秒衝刺迴圈拉伸越過一格讀來像原地顫抖，這就是為什麼線列步兵用跨體滑膛槍行軍而非同在骨架上的步槍衝鋒前進 |
| `run` | 循環原地奔跑 —— 騎士在跳躍中衝刺（僅騎士） |
| `attack` | 吃子落下的瞬間一次性揮擊 —— 火花、震動與碰撞定時到命中幀。對皇后與法師，同個片段是詠唱，其命中幀是火球釋放的瞬間；對大軍團的**站立**火藥階級，它是**射擊彈道**，以自己可讀的長度播放，命中幀在射擊上。元帥**沒有** `attack` —— 他從蹲下的 `aim` 開火（見*火藥戰鬥*） |
| `death` | 被俘虜的棋子在被溶解成灰之前播放的一次性倒下 |
| `reload` | 射擊後運行的一次性彈道 —— 火藥、彈丸、推彈桿。只有大軍團的四個火藥階級帶一個；仍然在開火的膝上重裝，砲兵在槍口 |
| `rise` | 單膝與雙腳之間的一次性姿態變化。作者製作了跪→站並以**兩個方向**播放：反向（`playKneel()`）讓元帥跪下，正向（`playRise()`）讓他站起。只有他有一個 —— 在臀部測量，它在 48 單位展開，到 70% 標記時站到 92，因此 `RISE_SPAN` 在該部分以兩個方向運行，從不顯示靜止的尾巴 |
| `aim` | 循環**瞄準畫面**在射擊前保持 —— 且對蹲下的槍手，*穿過*射擊：武器舉起並在射手安定時保持在身體上。拿破崙（手槍平舉）、線列步兵（滑膛槍抵肩，槍管追蹤目標）與元帥（單膝跪地，步槍舉起掃描）帶一個；只有砲兵沒有 —— 架炮*就是*它的瞄準。`setAimDrift()` 在射擊後將橫向掃描幾乎減到停止，因此開火的人看著他打中的東西而非重新掃視棋盤 |

接線方式（`src/scene/pieces.ts`）：

- **綁定骨架**的 GLB 是視覺 —— 普通 GLB 沒有骨架，因此綁定到它的片段不做任何事。每個動畫 GLB 貢獻一個片段，重新命名為 `idle` / `walk` / `run` / `attack` / `death`。
- 每個實例以 `SkeletonUtils.clone` 複製（從不 `Object3D.clone`）並擁有自己的 `AnimationMixer`。一次性使用 `LoopOnce` + `clampWhenFinished`，打擊在混合器的 `finished` 事件上交叉淡化回姿態。
- 片段根運動在 X/Z 上被剝除，因此棋子永遠不會走出其格子；死亡片段保留其運動使倒下讀來正確。運動片段因相同原因是**原地**迴圈 —— 棋盤旅行由容器補間擁有，因此帶有根平移的片段會使距離加倍。
- **預設控制*姿態*，非動畫。** `idleAnimations`（在**低**上關閉）是環境呼吸 —— 三十二個骨架每幀跳動，這是實際有成本的部分；沒有它，棋子保持其姿態的第一幀。**行軍、打擊與死亡在每個預設上運行**：行軍是一或兩個混合器一秒。`PieceView.returnToStance()` 在返回的路上尊重預設，因此應該站著的棋子在其第一步後不開始呼吸。
  - 這個旗標過去是一個 `characterAnimations` 開關控制姿態*與*行走迴圈，而 `detectQualityPreset()` 將觸控裝置送到**低** —— 因此每個手機在相同棋子仍在完整動畫中揮舞和死亡時讓雕像在棋盤上滑行。`navigator.deviceMemory` 是 Chromium 獨有，因此 iOS 回報無，未知被預設為 4 GiB 然後測試 `>= 6`：沒有 iPhone 能通過。未知記憶體現在被視為未知，當代手機從**中**開始。
- **片段以波次載入，非一次爆發。** 十二個骨架 × 五或六個片段是超過七十個 GLB；同時發射它們讓瀏覽器丟棄請求（`TypeError: Failed to fetch`）且棋子悄悄失去打擊，因此吃子看起來像棋子未被碰觸就死了。骨架及其 `idle` 先載入，然後 `PieceFactory.warmClips()` 以兩個下載寬度拉 `walk` → `run` → `attack` → `death` → `reload` → `aim`，每個到達的片段綁定到已經在棋盤上的棋子（`PieceView.installClip`）。**行軍**在打擊之前刻意預熱：任何遊戲做的第一件事就是移動棋子。
- **沒有片段就不播放節拍。** 吃子呼叫 `ensureClip` 取得攻擊者的打擊與受害者的死亡，因此戰鬥等待（最多 2.4 秒）而非跳過其動畫 —— 且 `glide()` 通過 `armStride()` 為它即將行軍的同一步做相同的事（最多 0.6 秒）。沒有第二個守衛，開頭一步在行走片段仍在空中時就被編排，棋子以凍結的姿態穿過格子：這是「這個階級失去了行走動畫」的確切症狀。
- **片段綁定到需要它的每個名冊。** 下載按 URL 共用，且 `bindClip()` 將結果交給*每個*片段地址匹配的名冊，而非僅第一個要求的 —— 因此沒有棋子因為孿生兄弟先到而失去行軍。伺服器沒有的片段 URL 在 `MAX_CLIP_ATTEMPTS` 次請求後註銷：皇帝的骨架在 R2 完全沒有重裝片段，追逐它讓他的每次射擊在節拍繼續前付出一輪完整的失敗提取。他改把手槍放下直到一個被生成。
- 如果打擊片段真的不可用，`SceneEngine.lunge()` 手動執行揮舞 —— 蓄力、扭轉、後仰，然後從上方揮下。傾斜通過 `PieceView.setStrikeTilt()` 保持並在混合器後重新應用，否則混合器擁有姿態。

### 行軍與腳步聲

`SceneEngine.glide()` 擁有每步一個行軍時脈（`src/scene/sceneEngine.ts`）：

1. `GAITS[kind]` 宣告每格步數、節奏、靴子音色與音量的階級。
2. `steps = tiles × stepsPerTile`，移動的持續時間是 `steps / cadence` —— 較長的移動花**更多步**，而非更快的滑行。
3. `PieceView.startMarch(clip, stepRate)` 重新定時行走迴圈，使一個步態週期在確實那個速率等於兩次腳步落地，因此骨架不能漂移出時脈。迴圈長度通過自相關腿骨的擺動從片段**讀出**（`gaitCycle()`，按片段快取）。將整個片段視為一個迴圈是讓沉重階級失去行軍的原因：`casual-walk-inplace` —— 國王、皇后、塔與砲兵的行軍 —— 是*三個*迴圈的 4.23 秒，因此要求的時間縮放是 3-4× 並飽和上限。然後腿以相同的固定模糊旋轉，與移動無關，與腳步時脈不同步，而塔特別讀來像滑行而無動畫。
4. `strideEasing()` 給移動一個推出、等速巡航與安頓。完全緩和的曲線會在固定節奏的兩端讓腳溜冰。
5. 每個跨過的整步觸發 `audio.footstep()`（按螢幕位置聲像、交替腳、音高抖動）加上接觸點的小沙塵飛濺。
6. 砲兵拖炮而非攜帶，因此它在行軍時車廂在軸上隨每次腳步俯仰並左右搖擺（`rumbleTrain()`，由 `settleTrain()` 放回水平）。野戰炮在行走的隊員旁邊滑行是塔看起來無動畫的另一半。

腳步聲在 `src/audio/audioManager.ts` 中完全合成 —— 一個低體撞擊聲代表重量，一個帶通雜訊瞬態代表鞋底，一個金屬餘震代表盔甲，每個 `FootstepTimbre`（`scuff` / `leather` / `plate` / `regal`）一個聲音。無資產，無延遲。

### 每階級打擊

近身節拍是一段編舞 —— 衝鋒、站定、打擊、崩潰 —— 但其重量從 `src/scene/sceneEngine.ts` 中的 `STRIKES[kind]` 讀出，因此相同的代碼承載步兵的刺擊與皇家處決。兵的線是原始節拍，保持原樣；其上面的一切都對它測量：

| 階級 | 在兵的節拍上疊加什麼 |
| --- | --- |
| 兵（`p`） | 基準：5.5° 鏡頭推進，火花，一次鏡頭震動 |
| 騎士（`n`） | 最快衝鋒，一道新月鋼弧穿過身體（`spawnSlash`），沿衝鋒線揚起的沙塵，輕微餘震 |
| 主教（`b`） | 僅安全網 —— 法師遠距戰鬥 |
| 城堡（`r`） | 最慢蓄力，混合中最重的揮舞，一道波動滾過石面（`spawnGroundWave`）帶第二回聲，低頻撞擊，長餘震 |
| 皇后（`q`） | 僅安全網 —— 女巫師遠距戰鬥 |
| 王（`k`） | 在打擊前降在受刑者頭上的光柱（`spawnPillar` + `judgementToll`），11° 鏡頭推進，金弧**與**金地面波，最長凍幀與餘震 |

支援視覺住在 `src/scene/strikes.ts`（`spawnSlash`、`spawnGroundWave`、`spawnPillar`、`spawnConquestClaim`）。每個建構一個一次性物件，從呼叫者的補間時脈動畫化並自行解構，因此它們都不需要在影格迴圈中的插槽；紋理與幾何是共用模組單例，由 `disposeStrikeAssets()` 釋放。揮舞、撞擊、鐘聲與征服（`bladeWhoosh`、`groundSlam`、`judgementToll`、`conquest`）在混合器中與腳步一起合成 —— 無資產。

### 佔領格子

所有三個戰鬥節拍 —— 近身、法術與火藥 —— 以相同方式結束：屍體被清除，勝利者行軍到格子上。那個到達過去以安靜移動獲得的相同一般著地咯咯聲強調，且*比平常更輕*的著地，因此實際贏得西洋棋遊戲的那一刻是戰鬥中最安靜的東西。`src/scene/sceneEngine.ts` 中的 `claimSquare()` 給它自己的節拍，在 `landOn()` 之後從 `runMove()` 觸發一次 —— 這意味著它涵蓋每條路徑，包括關閉電影效果時做的吃子和平面戰術地圖上做的吃子：

1. **`audio.conquest()`** —— 一雙靴子佔領石頭（低悶聲上的乾沙礫），然後一段銅管旋律奏出完全五度上揚，然後兩個高不諧和分音留下迴盪。每個音通過在攻擊時打開的濾波器從音下舀入，這就是讓它讀來像銅管而非鋸齒波的原因。其根音是 G3，與審判鐘被敲擊的相同基頻，因此兩者讀來像一個大廳在說話。完全合成，因此句號即使在冷取快取上也落在精確的影格上。
2. **`spawnConquestClaim()`** —— 勝利者顏色的一個寬環**緊密**畫在棋格周圍，收合時變亮，扣入軍隊自己的日爆記號並放開。兩個一次性圓盤；每個預設都夠便宜。
3. **棋子挺直** —— `drawUp()` 將肩膀從打擊向後仰並在 `outElastic` 上彈回水平，由運行時節點而非片段驅動，因此沒有動畫的骨架也得到它。傾斜，非姿態：它在回應前的停頓內完成，因為勝利之舞會讀來像棋盤在吊著。

一切都按 `CONQUEST_WEIGHT[victim.kind]` 縮放 —— 棋盤上屬於**受害者**的重量。較重的吃子將旋律根音降低最多半八度，延長其尾音，以第三個音加上八度，將環閉得更久並拋出更多碎片。因此皇后被擊倒聽來與兵交換是不同的，兩者都不需要自己的編舞。

### 遠距戰鬥（皇后與法師）

`src/scene/sceneEngine.ts` 中的 `RANGED_KINDS` 將皇后（`q`）與法師（`b`）的路由到 `playSpellCinematic()` 而非近身節拍，順序如下：

1. 施法者與目標轉向面對彼此；施法者不離開其格子。
2. `gatherSpell()` 在武器的施法點長出一個 `SpellOrb`（`src/scene/spells.ts`），在打擊片段蓄力的長度上，在上升電荷上向內拉餘燼。
3. `throwFireball()` 將法彈飛到目標胸口，沿平弧線，散落餘燼與煙霧；飛行時間按實際越過的距離縮放。
4. `spellBurst()` 著地 —— 閃光、火殼、餘燼雲、格子撞擊與鏡頭震動。
5. `slay()` 然後 `banish()` 完整運行，因此目標在施法者踏出一步之前**死了且消失了**，只有到那時 `glide()` 才行軍到清空的格子上。

丟多少火也是一個輪廓 —— `MAGE_SPELL` 對 `QUEEN_SPELL`。法師持小球，投擲一發法彈。女巫師聚集約一半長的時間，持大得多的球，並投擲**三連發**：兩個較小的前導從肩膀外側進來先拍在身上，然後是擊殺法彈，其爆炸是法師的 1.75×，並在格子周圍滾出一圈火焰。

施法點是掛在主要武器頭上的標記（`src/scene/weapons.ts` 中的 `focus`），每幀從即時姿態讀出，因此火焰掛在水晶上，無論施法手臂揮到哪裡。`SPELL_LOOK` 給每支軍隊自己的火。三個法術聲音（詠唱、施法、撞擊）在混合器中與腳步一起合成 —— 無資產。

**火的光來自固定池。** `SpellLightPool`（`src/scene/spells.ts`）在場景中一次建立三個點光源並按法彈借出。每個法彈建立的光源會讓分頁當機：three.js 以其場景的光源數作為著色器程式的鍵，因此大廳中的每種材質在戰鬥中重新編譯。共用光源從不移除*或隱藏* —— 不可見的光源從渲染狀態中移除，這與移除它完全相同地改變數量 —— 它們只被調暗到零並歸還。第四個同時的法彈只是得不到光源而非重新編譯，而池中在沒有後處理的預設上是空的。

吃子溶解是著色器注入：一個噪音場從腳底向上以發光的燃燒邊緣吃掉身體，同時整個網格褪色並散落向上飄離的光點。

### 火藥戰鬥（手槍、步槍、滑膛槍與野戰炮）

大軍團不用巫火戰鬥。`src/scene/sceneEngine.ts` 中的 `attackStyle(kind, arsenal)` 將**除重騎兵外所有階級**的路由到 `playGunCinematic()` —— 巫火節拍在此武裝下不可達，而重騎兵仍以軍刀縮短距離。節拍是：

1. 兩顆棋子轉向面對彼此；射擊者從不離開其格子。當槍管轉過來時聽到一個鎖、推彈桿或火繩桿聲（`audio.gunLock`） —— 那是擊錘被*扳起*，在扳機靠近前的節拍。
2. **跪到膝上**，對槍手其 `GUNS[kind].stance` 說他從石頭上戰鬥（僅元帥）。`PieceView.playKneel()` 在 `stance.drop`（0.85 秒）上**反向**運行他的 `rise` 片段，因此膝蓋以關節運動著地而非身體被混合向下，石頭在他到達的幀上聽到承受他的重量。
3. **瞄準。** `PieceView.playAim()` 循環瞄準畫面 `GUNS[kind].aim` 秒（0.3–0.55 秒）：武器舉起並*保持在*身體上。沒有瞄準片段的階級改為用手傾身進入射擊，因此槍總是在任何東西開火前被看見在瞄準。
4. **彈道 —— 或保持的跪姿。** **站立**的槍手以自己的可讀長度播放其射擊片段（`GUNS[kind].drill = { seconds, impact }），射擊在擊錘落下的幀離開（`impact`，片段的 0.5–0.64）而非劍士的預設 0.42；在預設*長度*上，射擊彈道在三分之一秒內結束，射擊讀來像從姿態中出現的閃光。

   **蹲下**的槍手完全不播放射擊片段，這就是 `stance` 的全部意義。生成器產生的每個射擊片段都從雙腳開始和結束 —— 元帥的 `Female_Crouch_Pick_Gun_Point_Forward` 在臀部測量，92 單位（站立）→ 68 → 回到 93 到 70% 標記，因此其作者製作的點火幀在 0.6 時以**直立**的人開火。在蹲下的 `aim`（臀部 48）與蹲下的 `reload`（42）之間運行，它站起來射擊並再次落下：一次射擊內的三次姿態翻轉，這正是讀來像上下彈跳的原因。因此他從**保持的跪姿**開火，而 `drill` 純粹成為節拍 —— 觸發器前 1.02 秒的保持瞄準，棋盤上最長的等待。因為槍口標記從即時姿態讀出，射擊仍然從膝蓋放下的高度離開槍管。
5. **扳機扣下**，在火藥點燃前 `GUNS[kind].lock` 秒。`audio.triggerPull()` 播放擊錘卡榫釋放、燧石刮過燧發槍片與引火藥點燃 —— 射擊的機械一半（見*擊發延遲*）。
6. 一個擊發延遲後槍回應：`spawnMuzzleFlash()` 在槍管口引爆裝藥（見*槍口閃光*），`spawnPowderCloud()` 在槍前留下一團煙霧 —— 滑膛為煤煙，步槍為淡灰（見*火藥煙*） —— `boreTrickle()` 在開火後讓槍管繼續冒煙，`audio.gunshot()` 在與閃光相同的幀上發射爆聲。
7. `flyShot()` 送彈丸**平且快** —— 無弧線，無緩和；平坦是區分槍與拋擲法術的東西 —— 拖著煙霧細線前進。*滑膛*的彈丸從視線偏離並回到身體上（見下方）；來福的彈丸是唯一飛真正線的一個。
8. 命中著地：彈丸自己的到達先（`audio.ballImpact()` —— 被身體悶響打斷的跳彈尖嘯），然後閃光、火花、棋格撞擊、鏡頭震動，以及野戰炮的滾過石面波動加長餘震。身體在彈丸進入的地方**裂開** —— 一個垂直於飛行線的光環，一個金屬碎屑錐拋回射擊者，以及一個由受害者自己材料製成的翻滾碎片場（見*彈丸到達的瞬間*）。**實心彈不停在人體內**：第二次短飛行帶鐵越過他一個半格並在石上跳開，拋出石屑與跳彈火花雨。
9. `slay()` 運行，然後 `banish()` 與**重裝彈道一起運行**，因此身體消失了且槍管在 `glide()` 走到射擊者到清空格子上之前重新裝藥。蹲下槍手的重裝從**他開火的膝上**提供 —— `reload()` 只將站立槍手交回其姿態 —— 一旦身體被清除，`riseToFeet()` 在正向 `rise` 片段（~0.9 秒，靴子聽到承受他的重量）上帶他站起，然後他才行軍。在膝蓋下去與格子被清空之間，他的姿態從不改變一次；瞄準畫面也在報告時幾乎減到停止（`setAimDrift()`），因此他保持看著他打中的東西而非重新掃視棋盤。

### 彈藥

**每根槍管發射自己的彈丸，每個都是生成的雕塑** —— `SHOT_MODELS` 命名每彈丸一個 GLB，`src/scene/ammunition.ts` 是備用鑄造廠，`GUNS[kind].ammo` 說明什麼被裝入哪根槍管。這裡沒有發光的點：黑火藥從不發射曳光彈，因此彈丸由其*形狀*、*金屬*與*運動*被讀取，只有鐵被允許發光。

| 彈丸 | 槍管 | 如何製造 | 如何飛行 |
| --- | --- | --- | --- |
| **`pistolBall`** | 皇帝、指揮官 | 從兩件模鑄出的鉛球：兩半合處的凸起縫、澆口殘樁，以及不完全圓的表面 | 繞其離開的軸翻滾；偏離線 ~0.9 口徑 |
| **`musketBall`** | 線列步兵、重騎兵 | 相同彈丸在 .69 且明顯更軟 —— 兩倍模變形，因為軟鉛被裝入骯挨的槍管會挨打 | 翻滾；**偏離 ~1.6 口徑** —— 棋盤上最胖、最不準確的彈丸 |
| **`minieBullet`** | 元帥-神槍手 | 車削成真實圖紙的輪廓：長尖鼻，帶**三個潤滑槽**的承載體（它們攜帶保持軟化熔劑的動物脂），以及**空心底座**，其裙被裝藥吹入來福線 | 繞自己的鼻硬旋轉並保持指向被發送到的地方。**零偏離** —— 軍隊中唯一真正的線 |
| **`roundShot`** | 砲兵 | 砂鑄鐵：一個被穩定雜訊**坑蝕**的二十面體，每六個頂點一個是真正的凹洞，鑄縫仍繞其中間 | 慢速旋轉，從槍口發光並**在大廳中冷卻**，拖著一團空氣，乾淨地穿過身體 |

兩種金屬服務於程序化備用，快取並共用：未拋光**鉛**（`0xb4bac2`，`metalness 0.62`，`roughness 0.44`）與**砂鑄鐵**（`0x3b3936`，`roughness 0.72`），其自發光按射擊動畫化。兩者刻意*不*保持全鏡面金屬並給一個自發光灰的地板，`legible()` 對每個生成雕塑自己的材質在載入時做相同的事。原因很直白：一個幾像素寬的近乎鏡面球在火炬照明的大廳中沒有東西可反射，因此它渲染為黑點且射擊看起來像從未發生。加熱的彈丸擁有自己的材質複製（雕塑的 `ownMetal()`），因此它的光可以在不碰到仍在空中的另一發的情況下冷卻。

### 讓射擊可見

一個真正的 .69 彈丸是人身高的五十分之一，大約百分之一秒穿過八個格子。誠實渲染它是一個像素一幀 —— 這正是為什麼槍火讀來像「閃光，然後屍體」。三個刻度修復它，且只有這三個被允許說謊：

- **口徑**（`AMMUNITION[kind].gauge`，1.7–2.6×） —— 彈丸被*繪製*為口徑的可讀倍數，而其飛行路徑、偏離與旋轉保持在真實數字上。炮彈需要最少幫助；米涅彈需要最多。
- **膠片速度**（`GUNS[kind].speed`，每格 0.082–0.125 秒，限制在 0.17–0.58 秒飛行） —— 夠慢以在彈丸離開槍口時撿起它並跟隨它進入身體。槍管間的順序保持真實：來福最快，野戰炮最慢。
- **鼻模糊**（`tracerTexture()` 在錐形上，`AMMUNITION[kind].streak × NOSE_BLUR`） —— 彈丸鼻上的一個模糊金屬錐，沿*旅行向量*而非看板化，按彈丸的實際速度（`haste`）加長並在前幾幀從一個殘根展開，因為射擊在移動前沒有模糊。它*與*彈丸一起騎，因此它說金屬多快而非它在哪裡 —— 這就是為什麼它現在保持其作者長度的一半且路徑分開繪製。

在這之上一個小**閃光**精靈帶著捕捉到的火炬光，使金屬在暗遠牆上註冊，且彈丸現在在*槍口外*（沿火線 `min(0.42, muzzleFlare(gun) * 0.44)`）而非在自己的槍口閃光與火藥庫內生成。橙色光精靈、借來的點光源與拖曳的尾跡仍然只屬於鐵。

### 沿飛行路徑的條紋

一切都釘在彈丸上，因此所有東西都*與金屬一起旅行*，沒有一個說去過哪裡：你注意到彈丸到達但從未看見它穿過。`src/scene/tracer.ts` 是缺失的一半 —— 一條短 3D 緞帶沿彈丸**實際飛過**的路徑橫掃，從槍口外到身體，每幀從自己的飛行樣本重建。

它是幾何，非看板，這買了三樣精靈不能的東西：

- 它**從任何鏡頭角度保持其形狀**，並被棋子與柱子像真實物件一樣遮擋，而非在射擊越過視軸時翻轉或游動；
- 它**在彈丸彎曲的地方彎曲**。滑膛彈丸在其 `sin(πt)` 偏離上從視線偏離並回到身體 —— 那條曲線過去藏在直線錐內，現在是關於滑膛槍射擊最可讀的東西；
- 它刻意**短**（`StreakLook.span`，4.2–9 個渲染彈丸直徑 ≈ 一格）。一條從槍口到受害者全長的條紋讀來像雷射，這是黑火藥從不是的東西。

截面是**三葉管**而非面向鏡頭的四邊形：無需查閱鏡頭，無翻轉，且夠便宜（按預設 12–26 環，`trailRings(captureParticles)`）以一次運行多發。兩層沿相同脊柱橫掃 —— 一個寬淡的擾亂空氣**護套**（`falloff 1.6`）與一條細亮**燈絲**在 0.42× 寬度，只在金屬後面的幾個口徑發光（`falloff 4.2`）。一層單獨讀來像霧或線；一起讀來像速度。環半徑在 `u^0.55` 上漸縮，亮度在 `u^falloff` 上，因此尾巴收成針尖並溶解而非在切邊上結束。

兩個細節讓它看起來不像被動畫化的網格。環幀從樣本到樣本**向前攜帶**（法線重新投影垂直於每個新切線）而非從世界軸重建，這就是在路徑轉彎處停止管可見扭曲的原因。尾巴通過**沿其段滑動最老的樣本**來修剪以保持弧長精確，從不丟樣本 —— 彈出一個讓尾巴每步向後頓一下，滑動它意味著尾巴以彈丸行進的相同速度溶解。緩衝區一次分配完整大小並通過 `setDrawRange` 繪製，因此尚未長到長度的條紋從不拖著陳舊三角形。

當彈丸著地，`releaseStreak()` 將緞帶交給 0.16 秒自己的淡出（`(1-t)^1.7`）而非在撞擊影格上刪除它：它在碎片與閃光下死亡，作為移動非常快的東西的殘像。每彈丸 ——

| 彈丸 | 跨度 | 寬度 | 讀來像 |
| --- | --- | --- | --- |
| **`pistolBall`** | 5 直徑 | 0.60 | 勉強半格的薄冷空氣 |
| **`musketBall`** | 5.6 | 0.74 | 胖、灰，且明顯*彎曲* |
| **`minieBullet`** | 9 | 0.48 | 軍隊中最長最細的條紋 —— 也是唯一直的 |
| **`roundShot`** | 4.2 | 1.00 | 短、寬、熱：發光鐵後拖著的焦灼空氣 |

### 槍口閃光

火焰必須由**發射它的彈丸**縮放，這就是為什麼 `GUNS[kind].flare` 是*比例*（4.4–6.0）而非世界單位寬度。`muzzleFlare(gun) = ball × AMMUNITION[ammo].gauge × flare` 是槍口所有東西的唯一真相來源：閃光、餘燼雨、借來的點光源的範圍，以及彈丸離槍口多遠生成。當閃火獨立於彈藥作者化時，兩個在彈丸變成 1.7–2.6× 口徑的雕刻時立即偏離 —— 彈丸最終比發送它的電荷更亮更寬，這讀來像彈丸被丟下而非發射。將兩者繫到一個數字意味著彈丸口徑的變化永遠不會讓它的閃火落後。時期火焰大約是 4–8 口徑，因此乾淨燃燒的步槍在範圍底部（4.9），野戰炮在頂部（6.0）。

閃光有四層深，因為單一加性精靈被限制在透明度 1 且根本無法變得更亮：

1. **星** —— `muzzleFlashTexture()`，看板化：十三個參差的花瓣延伸到精靈邊緣加三個長主射流，在一個保持**平坦白色到其半徑五分之一**的光環上。那個平台是重點：泛光通行只在已經裁剪為 1 的東西上起作用，因此建為禮貌漸層的閃光在少數像素上泛光且讀來像暗淡火花。
2. **核心** —— 一個純白小盤加性疊加在星自己的爆心上方。加性層疊是超越透明度 1 的唯一方法。它是最後一個變寬且第一個死的，這就是為什麼影格一讀來像引爆。
3. **射流** —— 塗抹錐，*非*看板化，其亮寬端在槍口，尖端沿瞄準線跑出。因此閃光*沿槍管*生長而非僅作為盤膨脹，它告訴眼睛彈丸剛去了哪裡。
4. **前導泛光** —— 沿火線一個槍管寬的第二個暖泡。

包絡帶與尺寸一樣多。火藥在一幀中點燃，因此整個堆疊在其生命的**前五分之一保持全亮**（`IGNITION`），然後才在 `(1-t)²·¹` 曲線上消退 —— 從影格一就開始衰減的閃光從不在 60 fps 下註冊。死亡的節拍帶著閃爍（`0.82 + 0.18·|sin|`），因為裝藥不均勻地熄滅而非在刻度上變暗，借來的光以 `fade × 38 × flame` 燃燒，距離隨電荷增長。

偏離不是裝飾。彈丸在未線膛的槍管中嘎嘎響時讓它旋轉，而旋轉的球彎曲 —— 這正是為什麼滑膛槍在一百步不可信。`flyShot()` 沿傾斜的橫軸在 `sin(πt)` 曲線上將彈丸向外出肚，因此它在中途達到峰值並回到身體上：明顯不是直線，仍然命中。

所有四個彈丸作為**生成的雕塑**飛行（`SHOT_MODELS`，每個在遊戲背後由 `primeShotModel()` 準備）。生成器將它們每個回報為*無方向*（旋轉體沒有內在正面），因此載入器取每個雕塑的**測量長軸**作為鼻而非猜測偏航常數，將其標準化為一個單位鼻到基底並居中。直到 GLB 到達，該類型被程序化轉向相同合約：**鼻沿 +Z，居中，一個單位長**，因此彈丸只按它的口徑縮放它 —— 且遊戲的第一發從不是空白。

### 彈丸到達的瞬間

以暖精靈泡結束的射擊是法術，非擊殺。`src/scene/shatter.ts` 用明顯**破裂**的東西替換那個節拍，且它刻意是幾何而非看板 —— 整個瞬間的重點是身體裂開了。四個東西在同一幀上觸發，以眼睛讀取的順序，所有東西在補間時脈上的**兩個實例化繪製呼叫**內運行：

1. **衝擊環** —— 一個垂直於飛行線的光盤（定向，非看板化），在它撞擊的表面彈開並在 0.18 秒內消失。唯一非物理的部分；它存在是為了說彈丸進入身體的*哪裡*。
2. **火花** —— 真實拉伸的幾何，非點。每個火花是一個沿**自己速度**指向的四邊片，因此它繪製一條在飛行時轉向且其長度追蹤速度的條紋：快時長線，耗盡時點。它們以錐向*射擊者*離開，因為金屬碎屑從被擊中的面脫落；它們在自己的時脈上通過每實例顏色從白→橙→暗紅冷卻；它們**閃爍**而非褪色；它們帶著跑完整但升力消失的完整在石板路上滑行；且大約六分之一被給長得多的生命，因此雨從不像開關一樣停止。
3. **碎片** —— 受害者材料製成的碎片：帶每實例顏色與價值散佈的粉碎四面體，在重力下繞自己的軸翻轉，以材料特定的恢復加切向摩擦與擊倒翻轉彈跳 `BOARD_TOP`，靜止躺在石上，然後在生命的最後四分之一被拉下，因此棋盤從不被留下散落。
4. **灰塵** —— 呼叫者疊在上面的薄霧，由 `impactDust(body)` 染色，因此它是剛破裂的東西的顏色而非射擊者火藥的顏色。

**碎屑由受害者製成，非彈丸。** `impactBody()` 將軍隊 × 階級映射到一個配方，因為打入黑曜石偶像的彈丸不能與打入羊毛外套的彈丸噴相同的砂礫：

| 身體 | 誰 | 飛出什麼 |
| --- | --- | --- |
| `marble` | 象牙王國階級 | 淡色碎片與亮灰塵，中等火花 |
| `obsidian` | 太陽帝國階級 | 最多碎片與最寬散佈 —— 玻璃*片*，因此長剃刀片（3.4× 片），近黑帶翡翠斑與翡翠綠火花冷卻 |
| `plate` | 重騎兵 + 任何軍隊的守護者 | 鋼金屬碎屑，少碎片，**棋盤上最亮的火花雨**（功率 1 時 30，10.5 公尺/秒），幾乎無灰塵 |
| `uniform` | 大軍團大衣 | 海軍藍羊毛、淺黃皮革、金色蕾絲與沙平黃銅；慢，吸收，落在哪裡（0.16 恢復），幾乎無火花 |
| `flagstone` | 大廳地板 | 石屑與長跳彈雨在棋格上滑走 |

**它破裂多嚴重來自彈丸**，非階級：`AMMUNITION[kind].shatter` 將數量、速度與大小一起縮放 —— 手槍彈 0.72，滑膛槍彈 1，米涅 1.24（較輕，但到達更快且仍旋轉），六磅鐵 2.5。而 `.through` 決定是否有出口金屬碎屑以及入口：軟鉛在黑火藥速度下變扁並停下，而旋轉的錐形彈與實心彈都出來並在已經前往的方向拋出第二個、更寬、更慢的錐。實心彈在身體外一個半格石上跳下得到它自己的 `flagstone` 碎片對準地板。

實例計數按 `captureParticles` 上限，因此整個效果隨圖形預設縮放，洞在 `postFx` 預設上拋出一個借來的點光源五分之一秒。

**黑火藥被錄製，不僅合成。** `GUN_AUDIO_URLS` 持有每槍管一發（手槍、滑膛槍、步槍、大砲）加彈丸撞擊；它們像死亡嘶吼一樣在音樂後串流，`GUNS[kind].voice` 說明階級發射哪一個。沒有東西是沉默的：完整的合成聲音獨奏直到片段已解碼。

關於生成的片段有兩件事不能信任，且 `analyseTake()` 在解碼時從音頻測量兩者而非相信檔案：

- **射擊實際在哪開始。** 生成的音效是*片段*，非事件：它以模型想要的任何房間音調打開。第一組槍管被測量在夏勒維爾的劈啪聲前有 **54 毫秒靜音**，且線膛槍管直到 **171 毫秒** 才達到峰值。從擊錘落下的影格從零樣本播放，爆聲因此落在槍口閃光*後*三到十幀 —— 射擊被看見，然後被聽到。播放現在從片段自己的開始播放，因此瞬態落在要求的瞬間。開始從**最大**的 4 毫秒窗找到，然後*向後*走到攻擊的腳；簡單的閾值穿越在這裡無用，因為它閾上房間音調並叫一個劈啪聲深 170 毫秒的片段「在 0 毫秒對齊」。
- **它有多大聲。** 錄製電平在 0.18 到 1.55 滿量程間回來 —— 9× 散佈完全壓倒了作者化的每槍管混合。每個片段現在被標準化為共同峰值（限制，因此吵雜的一個從不被提升為噪音），這就是為什麼 `volume` 無論哪根槍管在說話都意味著相同的東西。

多少合成聲音留在下面然後在 `SHOT_VOICES` 中**按槍管**作者化，非從口徑推導 —— 「這錄製有多好」不是口徑能表達的東西。滑膛槍的片段有四個中最硬的瞬態且只在它下面保留 34% 合成；燧發槍的錄製主要是大廳，因此它保留 60% 或射擊在它發生的幀上沒有邊緣。錄製的大砲帶來自己的牆回聲，因此合成的一個退到一邊。每射擊走音刻意保持在百分之幾：較大的速率變化會將瞬態從扳機扣下的幀上拖開，這是這絕不能做的事。

#### 擊發延遲

前裝槍是**兩個**聲音，非一個。擊錘卡榫釋放，燧石刮過燧發槍片，引火盤閃光 —— 然後槍管中的主裝藥才點燃，燧發槍上 40–70 毫秒後，用引信從點火孔觸發的槍更長。那個間隙是擊發延遲，它是真實射擊聽來像事件鏈而非單一的砰的全部原因。

`GUNS[kind].lock` 按槍管宣告它，引擎將兩半分開播放：`audio.triggerPull()` —— 擊錘卡榫斷開、燧石刮擦，然後引火藥的細嘶聲一直跑到報告 —— 在扳機被扣下的幀上觸發，`audio.gunshot()` 在一個擊發延遲後跟上，與槍口閃光同一幀。神槍手的手裝配件是棋盤上最快的點火（38 毫秒 —— 慢鎖會在預期射程讓射擊偏離），軍用滑膛槍粗引火且較慢（58 毫秒），野戰炮的點火孔是命令與爆炸間最長的等待（120 毫秒），帶有較低、較長的引信嘶聲而非燧石刮擦。沒有這個，報告是耳朵唯一得到的，而手指動的瞬間聽不見。

`GUNS[kind]` 持有槍管。皇帝的燧發槍刻意是棋盤上最安靜的擊殺 —— 乾劈啪聲，一縷煙，無奇觀。元帥的步槍是最長的屏息（0.62 秒瞄準 —— 跪下*就是*他的瞄準 —— 在 1.7 秒彈道前）且最平、最快的彈丸，比線的滑膛槍更少火焰：神槍手是乾淨的劈啪聲，非齊射。滑膛槍是胸悶響上的硬劈啪聲與真正的白煙庫。野戰炮是大廳中最響的東西，比國王的審判還響：次低音撞擊帶著從遠牆回來的報告。

### 火藥煙

煙是槍製造的最慢的東西。閃光是三幀，彈丸是半秒，但雲在兩者後仍長時間在格子上飄動 —— 因此 `spawnPowderCloud()` 建為空氣而非精靈彈出。它過去是少數看板出現在一個幀上，以等速直線向外滑動且一起變暗，這讀來像單個泡在開關。裝藥實際做三個不同的事，且煙庫的每個葉在**自己的時脈**上攜帶所有三個，從其絕對年齡積分（封閉形式，因此煙在任何幀率下相同）：

1. **噴口。** 氣體在大約十分之一秒內離開槍口，非一次，因此葉在 `vent` 上*依次誕生*（滑膛 0.17 秒，步槍的緊包裝藥 0.10 秒）且最早的氣體獲得最猛的推（`push = 1 − order·0.62`）。煙庫可見地*從槍口長出*而非出現在它周圍，冷的後期氣體留在槍口盤旋。
2. **滯留。** 那彈射速度幾乎立即被空氣吃掉 —— 每個葉行進 `jet/drag · (1 − e^−drag·age)`，即它猛衝也許一格前然後停下。從那裡只有浮力（它作為 `age²` *建立*，因為火藥煙在爬升前從槍口垂下）、大廳自己的氣流，與自己的湍流盤繞：一個每葉 `sin` 旋轉使煙在自身上滾動而非剛性滑動，帶精靈旋轉的角阻力。
3. **溶解。** 質量守恆而體積不，因此不透明度在淡出上攜帶 `(seed/width)^1.35`：煙變淡*因為它在擴散*。每個葉在 `age^0.55` 上膨脹（氣體熱時快，之後緩和）並保持自己的壽命，大約六分之一被給較長的 —— 煙庫淡入你可以讀取棋盤的霧且從不在單一幀上結束。

兩個共用觸感將它留在大廳中：`HALL_DRAFT`（每秒幾公分，兩支軍隊相同）是最終將煙庫*帶離*格子的東西而非讓它在哪裡做的變暗，`floor` 將任何垂到 `BOARD_TOP` 的壓平而非讓它沉過石頭。`GUNS[kind].smokeHang` 按槍管宣告停留 —— 皇帝的燧發槍 1.7 秒到野戰炮 3.8 秒 —— 且每個都活得比自己的射擊長。

**槍管在劈啪聲後繼續冒煙。** 煙庫做一次，在開火的地方做，留在空中 —— 空氣不跟人走。但骯髒的槍口繼續噴一兩秒，而*那*煙屬於武器，因此 `boreTrickle()` 在時脈上發射 `GUNS[kind].boreSmoke.wisps` 線，每個在它被做的瞬間讀取 `PieceView.muzzleOrigin()`。線在神槍手從跪姿放下步槍時可見地拖著槍口，每根線比上一根更細、更慢、更長壽，因為槍口在冷卻。

**步槍的煙是自己的。** `GUNS[kind]` 攜帶火藥的特徵以及槍口（`smokeTint`、`smokeDensity`、`fineSmoke`），因為發射小、緊包裝藥的線膛槍管幾乎完全燃燒它。神槍手的煙庫使用 `fineSmokeTexture()` 而非滑膛槍的煤煙團 —— 一個高調、低不透明度、更細的綻開 —— 染成固定淡灰（`0xdfe4ea`）而非陣營馬具，**0.74 密度**：夠薄以保持透過它看見目標。步槍比滑膛槍製造更少的煙的答案從不是讓它*更厚*：有**更多葉**（12 對滑膛槍的 8），每個更小，更快離開槍口，更快滯留，更用力抬升且膨脹更遠 —— 且它**停留 3.2 秒**，槍口滴流 1.5 秒後，因此射擊可以被看著分解。彈丸在途中拖著的線帶相同淡色，更短生命與更多升力。其他每根槍管保持髒的馬具染色煤煙（野戰炮 1.15 密度與 14 葉，皇帝的燧發槍 0.85 —— 一縷，無奇觀）。

棋子不被自己的裝藥推動，它被**拋**（`gunRecoil()` → `PieceView.setTrainRecoil(back, lift)`）：輪子離開石頭，槍口在十分之一秒內跳起，車廂在它仍向後跑時落下，滾一點，然後才在大半秒內被舉回標記。沙塵與砂礫在它開火的幀上從輪下錘出，轍在報告後立即砰地滑回，輪子落在它後面，大廳在射擊*後*一拍而非同時承受後座力的衝擊。每個聲音由 `calibre` 在一個混合器方法中合成 —— 無資產，因此齊射從不等下載。

**神槍手被觀看，非透過他看。** 步槍射擊過去從全螢幕瞄準畫面後編排（`SceneCallbacks.onScope` → `ScopeOverlay.tsx`，`.mc-scope`）：身體周圍的暗管，追蹤它的黃銅雙線瞄準環，從範圍滾動的每射手手震，將畫面拋離標記的後座力 —— 所有東西坐在棋盤上最硬的鏡頭推進（8.5°）上。所有東西都消失了，回呼與 CSS 包括，他的構圖現在是線列步兵的（5.5°）。

原因是兩個效果在競爭同一個瞬間。疊層將擊殺*帶出*大廳 —— 你停止看著戰場上的男人並開始看著介面 —— 且彈道必須被拉長到 2.1 秒以給管子東西填。讀來像神槍手的東西簡單得多：**他跪下單膝來射擊，且僅此而已。** 那個蹲下過去是他的永久姿態（一個在整個遊戲蹲在掩體後的棋子，這就是為什麼關於射擊的任何東西看起來不像瞄準的動作），因此順序現在是
站 → 蹲 → 平舉 → 開火 → 在膝上重裝 → 站起 → 行軍，所有東西在大廳其餘部分所在的世界空間中。

**而且他在整個射擊中保持那個蹲姿。** 將蹲姿放入節拍只是工作的一半：然後姿態必須在它中存活。在蹲下的 `aim` 與蹲下的 `reload` 之間坐著一個在臀部測量站立 → 蹲 → 站立的*射擊*片段，其點火幀在回去的路上 —— 因此男人站起來射擊並在每次射擊落下兩次，且建在一個乾淨蹲姿周圍的節拍讀來像彈跳。片段名字中沒有任何東西告訴你這個；只有它的臀部軌跡。蹲下射擊因此**沒有射擊片段**且從保持的瞄準開火，`GUNS.b.stance` 宣告蹲姿因此引擎知道哪個姿態擁有射擊，且剩下的兩個姿態變化是從一個生成的片段的真實運動 —— `Kneel_on_One_Knee_and_Stand` 反向下去，正向上來 —— 而非兩個高度間的交叉淡化。

**槍去手臂去的地方。** 以固定體空間角掛在手骨上的道具適合靜止的刀，但它讓步槍在瞄準片段中直上。槍支因此在 `src/scene/weapons.ts` 中宣告 `hold` 且其角度每幀針對活骨架重新求解（`AttachedArms.align()`，在混合器後立即呼叫）：`longArm` **沿射程**佈置 —— 沿人物自己的前方，因為射擊者已經轉向面對他射擊的東西 —— 兩個拳頭只供應橫傾與仰角，因此平舉的滑膛槍與身體約呈 20° 且槍托在射擊肩；`sidearm` 通過手腕跟隨前臂，向人物前方舉起因此垂下的手臂低持手槍而非瞄自己的靴子。滾來自槍管繞橫軸俯仰四分之一圈 —— 直立時扳機護圈向前，平舉時向地板，中間無翻轉。攜帶的槍免除保持接地軸離開棋盤的地板間隙夾，這就是為什麼蹲下的神槍手握著他的步槍槍托底板。

**拳頭不跨在槍管上。** 長臂過去從兩個拳頭之間的向量*直線*取槍管線，假設抵肩片段將支撐手放在護木上。在實際射擊的骨架上測量，它不是。大軍團的瞄準片段是射箭片段，拳頭在**胸前並排**：手線沿人物的橫軸跑 0.90–1.00，沿其前方留下幾乎沒有 —— 且被用作槍管*方向*的殘餘在迴圈中多次變號。線列步兵的瞄準在一次掃描中讀前 = −0.24、−0.23、+0.27、+0.54、+0.40、−0.22、+0.02、−0.28，其射擊片段在作者化的點火幀 −0.26 —— 因此滑膛槍在指向射程與指向回越過擁有者肩膀之間擺動，且**射擊從反向一半被取**。神槍手的步槍因相同原因在其裝藥週期的所有九個樣本上向後走。手槍從未顯示它，因為 `sidearm` 規則總是帶著前方偏置；長臂只是缺乏等效的保證。它現在有了，兩個骨架上的每個片段（姿態、瞄準、打擊、行軍、重裝、站起、死亡）在前方 3–22° 處，無處變號。

射擊從槍本身離開：`src/scene/weapons.ts` 中的 `muzzle` 標記掛在每個槍管口（手槍、滑膛槍、炮膛）並每幀從即時姿態讀出，就像施法者的 `focus`。**野戰炮是拖行的道具**，非手持的：它以自己的輪子、車廂、轍與帝國鷹掛在雕塑根上，在體軸中，因此它隨衛士行進與轉向但不受骨架影響 —— 砲車在隊員蹲時不該蹲。閃光燈從相同的固定 `SpellLightPool` 借來。

## 拿破崙武裝

其他每支軍隊從基本體武裝，且應該如此：幻想巨劍沒有原件可以錯。大軍團的武器有。1777 夏勒維爾、An XI 騎兵軍刀與 An XIII 軍官燧發槍是被記錄到黃銅配件的物件，而一個的方塊圓柱版本在否則是真雕塑的手中讀來像玩具 —— 因此所有六個都是**生成網格**，列在 `ARM_SCULPTS`（`src/assets/generated.ts`）：

**劍是真實的長度，且它持在人物自己的剪影外。** 兩者都容易以看起來像壞模型而非錯數字的方式錯。皇帝的佩劍被裝在身高的 0.72 —— 1.26 公尺刀，比兵的 An XI 長，站在 1.69 公尺的人身上 —— 而每把拿破崙刀靜止在 `(-0.05, 1, 0.14)`：直上，稍微*向*脊柱傾斜。拳頭坐在約半身高的地方，因此任何比半身長的東西都越過王冠，且內向傾斜沿剪影中間走上去：那把佩劍在 x = 0.219 越過頭高，雙角帽的確切邊緣，因此從棋盤鏡頭皇帝的自己的刀被畫過他的臉。以測量修復，非口味 —— 佩劍是 0.54（95 公分全長，因此*比重騎兵的 0.63 短*，已經對了）且佩劍 0.58，而 `BLADE_AT_REST` 將所有三把斜出 ≈27° 且向前 ≈15°。刀現在從拳頭離身而去，在喉結高度而非帽子上方達到頂點，讀來像開放半格中的對角線。備用基本體只在刀縮短，從不刀柄：刀柄是手的大小無論刀做什麼。 | 拿破崙 / 指揮官 | An XIII 軍官燧發槍 | 方格半槍托，鍍金側板與底板，黃銅前帽 |

困難的部分不是下載它們。**生成的武器以任意姿態到達**：重騎兵軍刀測量 0.97 × 1.00 × 0.96 因為它沿自己邊界框的對角線躺著，因此檔案中沒有任何東西說刀跑哪個方向，哪端是尖，或扳機護圈在哪側。與其目測六個旋轉，`src/scene/armoury.ts` **測量**每個雕塑並將其裝入基本體作者化的確切局部框架 —— 長度上 `+Y`，底部在原點：

1. 從頂點雲的主軸取**長軸**（邊界框不能回答對角線模型這個問題 —— 三邊相等且沒有一個是刀）。
2. 從每端的截面取**哪端是尖**：槍口、刺刀與刀尖漸細，底板與碗護手不。馬雷諾劍刀柄最後到達且手槍槍口先；兩者都不需要特殊情況。
3. 從其餘兩軸取**滾**。刀保持其平面穿過揮舞（`±X`，匹配 `curvedBlade`），因此雕刻的佩劍仍然刃先揮。槍的鎖平面站在槍管自己的平面中（`±Z`），扳機護圈側通過從**槍口向外走到槍托**找到：槍口後面的切片是裸槍管，底部四分之一都是木頭與配件，且槍的槍托掛在槍口*下方* —— 因此那兩個帶之間的偏移指向底部，無論什麼其他東西被栓在武器上。這就是為什麼 `gunOrientation` 的承諾（直立攜帶時護圈向前，平舉時向地板）對沒有人手動旋轉的網格成立。

   這從**質心**讀取直到它咬：槍口三分之一對整個頂點雲的中間，這只有在除了槍的東西不將質心拉過槍口時才是相同的答案。凡爾賽步槍做到了 —— 它的鬆背帶環在槍托外武器長度的 `0.34`，步槍自己橫向厚度的四倍（`0.087`） —— 且它將質心拖過槍口。兩個長臂因此被裝**上下顛倒**：背帶越過槍口，鎖與扳機護圈轉向天空，在每個線列步兵與每個攜帶它的神槍手的每個片段中。燧發槍手槍沒有背帶來愚弄測試且在任一規則下讀來相同，這就是為什麼皇帝的握持從未看起來錯。
4. **哪個方向** —— 那個滾的*號*，特徵向量不能給：`±narrow` 都將平面放在揮舞上，因此回來的那個取決於雅可比掃描碰巧落在哪裡。在直刀上那不可見；在曲刀上是整個剪影，這就是為什麼皇帝被看到像鐮刀一樣握著他的佩劍。刀因此由**自己曲線的弓**解決：腹部 —— 凸側 —— 放在 `+X`，`curvedBlade` 揮向且 `knuckleBow` 凸向的側，在這些雕塑站立的基本體中。直佩劍沒有曲線可讀（馬雷諾劍弓其長度的 0.03%），因此它退回刀柄自己的塊，在佩劍上是護指。

   那個腹部在*人物*上朝哪個方向是安裝者的業務，非裝修者的：`restOrientation` 投影**身體的**前方，且身體的前方不隨手鏡像，因此道具自己的 `+X` 落在身體的 `+X` 上 —— 人物的左 —— 無論哪個拳頭握著它（測量：雙手 `(0.90, ∓0.45, 0)`）。`edged` 刀因此在 `+X` 是*外側*的拳頭中滾半圈（`EDGED_FLIP`），因此腹部總是弓過身體且尖掃離擁有者。弓另一邊，在皇帝自己的骨架上，他的佩劍來到靜止，尖在 0.80 外與 1.68 上，在 1.70 公尺的人物上 —— 其切線轉回越過他雙角帽的冠。弓過，尖繼續向外（0.85）且越過他清楚。只有三個曲拿破崙刀被標為 `edged`；直劍滾半圈看起來相同，因此中世紀與太陽武裝不受影響。

每武器只有兩個數字被作者化：**拳頭**與**槍口**，作為武器長度的分數，因為沒有測量找到扳機。兩者都是從每個雕塑自己的截面輪廓讀出 —— 鎖的凸起，護手與劍首之間的間隙 —— 且落在它們替換的手造道具的百分之幾內（步槍的拳頭在其長度的 0.30 對基本體的 0.30；滑膛槍的槍口在 0.80 對 0.77）。在滑膛槍上標記是刺刀**套筒**，非刺刀尖：閃光必須離開槍管，非其外的刀。`src/scene/armoury.test.ts` 將一把基本體造的劍與滑膛槍扔進隨機姿態並檢查它們回來站在底部，尖向上，護圈向前 —— 一個**背帶**滑膛槍另外，其環作者化得夠遠偏離底部將質心拖過槍口，因此滾永遠不能悄悄退回質心測試 —— 且一個**掃過的佩劍**從滾的兩半餵入，必須從任一回來腹部在 `+X`，因此鐮刀不能回來。

下游所有東西都不受交換影響。雕塑供應握把與槍口；*配置*仍然擁有靜止角、腕偏移與姿態驅動的 `hold`，因此神槍手仍然蹲下與平舉，皇帝仍然低持，且 `muzzleOrigin()` 仍然找到槍口。雕塑**與名冊一起下載**（`armSculptWarmJobs`，在 `src/scene/gltfQueue.ts` 中的共用視窗中）而非在其後，因為棋子在建構的瞬間就武裝 —— 晚到的武器是遊戲其餘部分從未看到的滑膛槍。幾何與紋理跨軍隊共用，只有材質是每棋子（高亮、淡出與溶解寫入它們），且任何下載失敗的雕塑直接退回基本體：普通滑膛槍優於無武裝的士兵。

## 替換為自己的模型

每支軍隊是 `ARMY_SKINS`（`src/assets/generated.ts`）中的一個條目 —— 標籤、簡介、階級名稱、武器家族、雕塑 URL、片段 URL 與語音：

```ts
export const ARMY_SKINS: Record<ArmySkinId, ArmySkin> = {
  ivory: {
    label: "Ivory Kingdom",
    arsenal: "kingdom",   // src/scene/weapons.ts 中的武器家族
    native: "w",          // 它被繪製的一方
    still: { k: "…king.glb", q: "…queen.glb", /* … */ },
    animated: { /* 綁定骨架 GLB + 每階級每片段一個 GLB */ },
    cries: { /* 每階級一個語音 */ },
  },
  /* sun, empire … */
};
```

第四支軍隊是那個條目加上 `src/scene/weapons.ts` 中的一個 `LOADOUT` 行；然後它自己在**設定 → 軍隊**中出現（面板渲染 `ARMY_SKIN_ORDER`）。

將 glTF/GLB 角色放入 `web/public/models/` 並將條目指向 `/models/your-king.glb`。需求：

- **方向** —— Y 向上，面向 +Z，或在同一檔案中編輯 `PIECE_MODEL_ORIENTATION`；載入器從宣告的前/上軸推導修正四元數。
- **縮放** —— 任意。`PieceFactory.normalize()` 測量模型，將其重新縮放為 `PIECE_HEIGHT`（`src/scene/pieces.ts`）中的高度，在 X/Z 上居中並在 Y 上落地。

`PIECE_HEIGHT` 刻意是**兩個層級，非六個**。棋盤只需要在鏡頭距離上關於棋子說一件事：那是兵，還是某個人。因此騎士、法師與塔守護者與皇后站在皇家帶中（0.98 / 1.00 / 0.99 對她的 1.00）且只有國王在 1.12 上升；兵站在 0.78 的較低層級。它們舊的 0.84-0.88 讓它們只比兵高一手，而三個軍官讀來像兵是說謊的棋盤。掛在棋子上的所有東西都跟隨數字 —— 其王冠上方的紋章，其點選碰撞體，其持有的武器，溶解從其下燒上的底線 —— 因此其餘的是一次編輯，有兩個值得注意的例外：

- **紋章與地圖標記隨它們重新排名**（`BADGE_SCALE`、`TOKEN_SCALE` 在 `src/scene/rankBadges.ts`）。小棋子紋章飄在皇家尺寸人物上方讀來像尺寸不足的貼紙，且平面頭頂地圖保持相同兩個層級因此切換視圖不會悄悄重新排名軍隊。
- **兵不是標記**（0.78，從 0.70 上調）。棋盤上的三十二個棋子中十六個是兵，因此它們主要*是*大廳；在 0.70 男人只站了他所佔據格子的三分之二且讀來像他格子上的標記而非佔領它的士兵。0.78 仍然在軍官帶下留了五分之一的格子日光，這是保持兩個層級在鏡頭距離上可分離的東西。
- **砲兵的炮對隊員縮放，並從其履帶付錢**（`WeaponSpec.bulk` / `WeaponSpec.track`）。一個真正的格里博瓦爾 6 磅炮在輪子上滾動約人身高的五分之四且比人高；在舊的 `bulk: 0.85` 這炮的輪子只到砲兵衛士的高度的三分之一，因此階級讀來像推玩具的軍官。它也不能簡單放大 —— 一格是 `TILE` 寬，且均勻生長的車廂將輪子放在鄰居棋子的格子上。因此 `bulk` 升到 **1.22**（輪子約在衛士高度的一半，轍到槍口剛好一格內）而 **`track: 0.8`** 在*自己的 X* 上擠炮 —— 軸。那是眼睛不審計的軸：輪子站在 YZ 平面中，因此變窄履帶只讓它們的輪胎變薄，從不把輪子變成橢圓。公園拉到 `(0.2, 0, -0.04)` 且拖行偏航從 0.14 緩和到 0.07 弧度（偏航以長度換寬度），大炮突出其格子 **0.03 單位而非舊的 0.11** —— 炮大一倍半，在鄰居的線中更少。
- **材質**在每實例複製並在 `applyFactionLook()` 中按陣營染色。

如果綁定骨架模型下載失敗，載入器退回靜態雕塑，如果那也失敗，退回程序化基本體人物 —— **遊戲始終保持可玩**。

要動畫化自己的角色，用綁定骨架 GLB 加每片段一個 GLB 填充軍隊的 `animated` 名冊；任何缺少的片段只是跳過（沒有 `walk` 片段只是那個階級滑行），且下載失敗的片段在下次遊戲需要時按需重試。

若要發佈，壓縮 GLB 而非從遠端主機串流它們：

```bash
bunx @gltf-transform/cli optimize king.glb public/models/king.glb \
  --compress draco --texture-compress webp --texture-size 1024
```

## 音效

MP3 被串流一次並解碼到 Web Audio 緩衝區：一個大廳環境底，**每戰場一個配樂**，一個在將軍和殘局時交叉淡入的張力主幹，加上落子、吃子、將軍號角與號角一擊。

**每個地圖有自己的音樂，且沒有地圖的音樂比另一個大聲是意外。** 七個配樂從生成器在 -12.8 到 -33.4 LUFS 間回來 —— **20.6 LU** 散佈。在一個共用底電平下，「哪個地圖最大聲」只會由哪個渲染碰巧最熱決定，因此每個音軌被測量並調平到原始圍城配樂的 -18.5 LUFS，其餘的混合 —— 敲擊、嘶吼、鐘聲、槍火 —— 在其下平衡。錄製的火藥已經得到的相同紀律。

它們也不是透過將最後樣本對接到第一個來循環，因為這些音軌不是為存活而寫的：兩個結束時超過一秒靜音同時以全電平打開（洞，然後震動），且兩個更多在最後樣本仍在播放。每個配樂的真正音樂窗被測量 —— 頭尾靜音到 -50 dBFS 地板的 50 毫秒 —— 且混合器*在那個窗內*循環，在等功率曲線上交叉淡入自身，因此接縫聽不見而非一分鐘的最大事件。切換戰場在 2.6 秒上交叉淡入兩個配樂；在第一點擊前選的地圖只是開始的那個。死亡嘶吼來自各方招募的軍隊（其 `ARMY_SKINS` 條目上的 `cries`）並在混合器解鎖後懶載入，因為它們只在吃子時需要；每個是真正一秒的片段，按死去棋子的螢幕位置聲像並按播放音高抖動。它們按 URL 快取，因此來回切換軍隊不花任何東西。

所有三支軍隊都有自己的一組六，且這些組是針對那支軍隊死去的方式寫的。大軍團的是槍擊反應而非近身嘶吼 —— 拿破崙咬著牙齒悶哼，指揮官吸一口氣讓低氣嘆飄走，元帥在他開火的膝上被打，重騎兵的吼叫被他的頭盔框住，砲兵衛士的呻吟隨他的重量垂下，線列步兵的叫聲年輕、細且突然中斷。

腳步、木板著地敲擊、格子易主時發射的征服動機（`conquest()`）、身體倒下與 UI 嗶聲用振盪器與噪音緩衝區合成 —— 無檔案。所有東西通過一個主增益路由供靜音切換，且播放僅在使用者第一次手勢後開始（瀏覽器自動播放政策）。

> **關於託管的資產。** 模型與音效預設從 `src/assets/generated.ts` 中列出的遠端 URL 串流。如果你為生產分叉這個專案，將它們鏡像到 `web/public/` 並更新那些常數，使你的建置不依賴別人的 CDN。

## 讓大廳貼合螢幕

`scene/viewport.ts` —— 引擎中的每個鏡頭都是針對寬桌面視窗作者化的，而透視鏡頭的 `fov` 是它的**垂直**角。因此螢幕越窄，棋盤的*寬度*適合畫面的越少：在直立手機上（長寬比 ≈ 0.46）46° 鏡頭只看到一半的線。且修復從不是「直接拉回」，因為**柱廊站在半徑 12.5** —— 一個拖過它的鏡頭將大廳自己的柱子與幕牆放在玩家與棋盤之間。

因此構圖是**求解的**，非作者化的。給定棋盤的範圍（八條線加棋子及其紋章的邊距），引擎計算出距離與鏡頭將整個棋盤放在*窄*軸上，然後將額外距離作為**高度**而非地面範圍 —— 鏡頭爬過柱廊而非退入其中。

| 螢幕 | 鏡頭 | 距離 | 地面範圍 | 高度 |
| --- | --- | --- | --- | --- |
| 桌面 16:9 | 46.6°（作者化） | 10.5 | 8.6 | 6.4 |
| 手機，橫向 | 46.6° | 10.5 | 8.6 | 6.4 |
| 平板，直向 | 63.6° | 10.5 | 7.7 | 7.5 |
| 手機，直向 | 68° | 14.5 | **10.6**（柱內） | 10.3 |

桌面視窗永遠不碰任何這些並保持其作者化的鏡頭。

求解的構圖還帶什麼：

- **棋盤永遠不會被大廳隱藏。** `confineCamera()` 每幀運行：任何超過半徑 11 的地面範圍被轉換為高度，保持與正在構圖的東西相同距離。環繞控制只能獨立地限制角度與距離，因此低角度的長拉回過去直接穿過柱子 —— 這就是這個 bug 關閉的地方。開場飛入豁免：它刻意從牆外進來。
- **展示跟隨機構提前自己解決那面牆。** 一個在平滑運行後修正*鏡頭*的網對滑鼠上的手很好，但它對一個在近方每步要求非法眼的機構是錯的：每幀追逐向外走，牆把它推回來，高度通過平方根回來。針對沿近線行軍的棋子模擬真實迴圈，夾在 **98% 的影格上**觸發，使鏡頭的平均幀間急拉加倍並在單幀中飆到**螢幕高度的 0.5%** —— 人們在展示模式中看到的顫抖。`solveFollowEye()` 現在在平滑*之前*將機構的地面範圍切到大廳有空間的地方，先從距離（18%）付，然後才從仰角付。與夾相同意圖，但連續：跟隨時夾從不觸發，急拉下降 ~11×，且眼睛比舊修正留的**更低**（在最壞角落 7.4 而非 9.6）。
- **跟隨機構傾向而非追逐。** 將棋子死置中讓眼睛橫向拖了整個棋盤寬 —— 這就是首先推它進入牆的地方。它現在走到動作的 72%：棋子坐在偏中心五分之一的影格中，其餘位置保持在畫面中，且鏡頭在步間明顯少移動。
- **手機從不給近地角。** 在視線高度棋盤是一條線且螢幕全是大廳，因此手持視角限制在地平線上方 ~20° 且從高處構圖 —— 這也意味著點擊落在手指實際在的格子上。捏合也不能比 5.8 單位更近，因此鏡頭不能埋在前列內。
- **2D 戰術地圖以相同方式求解。** 其 28° 頭頂鏡頭在手機上顯示六條線；它現在開到長寬比需要的任何角度（直向約 50°）並保持其距離。
- **戰鬥鏡頭推進是比例，非常數。** 5.5–8.5° 推入在 68° 構圖上幾乎不註冊，因此每個推進按生效的構圖縮放。在戰鬥中旋轉手機也不再恢復錯誤的鏡頭 —— 節拍讀取即時構圖而非打擊開始時捕獲的值。
- **旋轉裝置重新構圖棋盤**（保持你在看的那一側），而滑動的瀏覽工具列不會：鏡頭僅在長寬比真正移動時重新求解。
- **手持是能力測試**，非使用者代理猜測：手持尺寸螢幕上的粗糙指標。手機在桌面模式與窄桌面視窗都得到相同處理。
- **介面在手機上兩端收緊**：34px 圖示按鈕，緊湊的回合石板，以及兩個在鏡頭選單中重複（翻面）或被平台忽略（iOS 全螢幕）的控制項讓出其在行中的位置。
- **劉海與主畫面條被尊重。** 大廳本身邊緣到邊緣繪製（`viewport-fit=cover`），但你必須讀或按的任何東西都不是：每個釘在螢幕邊緣的表面在該邊緣支付 `env(safe-area-inset-*)` —— 見[有劉海手機的安全區域](#有劉海手機的安全區域)。

## 有劉海手機的安全區域

在帶動態島或劉海的 iPhone 上，回合石板與圖示列被繪製在*切口*下方，且紀事符印坐在主畫面條後方。

**原因是一個缺少的代幣。** 介面以純內邊距（`p-3 sm:p-4`，`bottom-0 left-0`）對原始可視區域佈局，且文件的 viewport meta 沒有 `viewport-fit=cover`。沒有那個選擇性加入，iOS 回報**每個** `env(safe-area-inset-*)` 為 `0px` —— 因此即使 CSS 要求了插入，它也會被兩手空空地交給。螢幕對 3D 大廳也是真正的邊緣到邊緣，這是我們想要的；只有介面需要拉入。

**修復** —— `web/index.html` 中的 `viewport-fit=cover`，然後 `medieval.css` 中的四個變數（`--mc-safe-top/right/bottom/left`），每個邊緣釘付的表面在**自己的邊緣且僅此**上花費：

- **頂列**（`.mc-hud-top`） —— 切口的頂部插入，加上兩個水平插入，因為橫向時切口移到側面且回合石板是它下面的第一條。底部邊緣保持不動：列只向下長。
- **紀事角落**（`.mc-hud-corner`） —— 主畫面條的底部插入，側切口的左插入。其底內邊距仍隨螢幕階梯 0.5 → 0.75 → 1 rem，因此插入加到正確數字而非替換它。
- **AI 對戰 AI 傳輸、乾淨擷取按鈕、影格計數器、側列** —— 每個從其停靠的角落移開。傳輸的 `max-width` 也減去水平插入，因此它在圓角下換行而非跑。
- **全螢幕面板**（選單、設定、結果）使用 `.mc-modal-pad`。變暗的背景刻意留在 `inset-0`：插入它且發光的劉海旁帶中看到大廳。只有裡面的內容被填充。
- **提示工具** 將其寬度對*安全*寬度上限，因此一個在橫向劉海旁打開的不被它裁剪。

所有四個變數在沒有切口的每個螢幕上解析為 `0px`，因此桌面與 Android 佈局是逐位元組與它們相同的。這裡沒有任何東西是使用者代理檢查。

## 分享卡片

貼到 X、Discord、iMessage、Slack 或 Facebook 的連結過去展開為**純文字**：頁面帶了 `og:title` 與 `og:description` 但**沒有 `og:image` 且沒有 `twitter:card`**，且那些爬蟲從不運行應用程式 —— 它們讀一次原始 HTML 然後離開。WebGL 大廳對它們不可見，因此沒有東西可顯示。

`web/index.html` 現在附帶完整卡片，`web/public/banner.jpg` 是圖片：

- **`twitter:card` 是 `summary_large_image`。** 沒有它 X 在文字旁畫一個小方形縮圖而非全橫幅，即使給了圖片。
- **圖片 url 是絕對的**，非 `/banner.jpg`。X 的爬蟲悄悄丟失相對圖片路徑。它出現三次 —— `og:image`、`og:image:secure_url`、`twitter:image` —— 因為較舊的刮板每個看不同的。如果網站換域名，更改所有三個（與 `og:url`）。
- **`og:image:width` / `height` 被宣告**（1600×900，16:9），因此卡片在圖片下載完成前保留正確形狀且沒有字母框。
- **JPEG 在 1600px 寬，~355 KB。** 來源橫幅是 1672×941 PNG 在 **2.9 MB** —— 在 X 的 5 MB 上限下但夠慢，逾時的爬蟲可以在提取中途放棄並快取遺失。相同圖片，**8× 小**。
- **`og:image:alt` 與 `twitter:image:alt`** 為用螢幕閱讀器讀時間軸的人描述棋盤。

`public/robots.txt` 已經明確允許 `Twitterbot` 與 `facebookexternalhit`，因此沒有其他東西擋路。爬蟲積極快取：更改後，在 X 的 Post Inspector 或 Facebook 的 Sharing Debugger 中重新刮 url 而非等待快取失效。

## 瀏覽器支援

任何有 **WebGL 2** 與 **Web Audio** 的瀏覽器：當今的 Chrome、Edge、Firefox 與 Safari 16+，在手機、平板與桌面上。支援觸控環繞、捏合縮放與點擊移動，構圖為繪製它的螢幕求解（見[讓大廳貼合螢幕](#讓大廳貼合螢幕)），且在窄螢幕上走棋紀錄離開側列為角落按鈕，因此棋盤保持整個可視區域。

在 Linux 上，先檢查 `chrome://gpu` / `about:support`：沒有硬體加速瀏覽器退到 llvmpipe，場景由 CPU 渲染。遊戲仍然運行 —— 見[黑畫面復原](#黑畫面復原) —— 但預期低預設幀率。
